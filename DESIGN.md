# Alex Lin — Portfolio UI Design

A fictional bilingual portfolio for an AI Product & Growth Lead. The reader should recognise the person's focus, scan the three distinct cases, and enter one complete case with one click. This is an open-source teaching example, never evidence of a real person's career.

## Visual direction

Three sentences, and they are meant to be falsifiable for this person rather than reusable for anyone. The page is mostly numbers read in sequence — a 28-day synthetic dataset, weekly totals, ROAS ratios — so the canvas is a warm paper sheet (#f4f5ef) that can be read at length without the glare of pure white, and the ink is a forest green (#233b32) rather than black, because the only colour this material already carries is the green line of a growth chart. One acid-lime (#dfef85) exists solely as selection and focus-on-dark; it is deliberately not the brand green, because a highlight the same colour as the brand disappears into the thing it is meant to point at. Lilac (#dedcf3) and sand/ochre (#ead9bc / #7c5312) are cover tints that let the three cases be told apart in the index before their titles are read.

Swap test, run against two other fields rather than asserted. A photographer's index needs a grid of images at their native ratios with a caption each; this structure hands the reader a 66ch prose measure (68ch for the small-text notes, after a 78ch limit was measured over the line it was meant to cap; the widest prose line anywhere now measures 70.4ch across nine viewport widths, 360–2559) beside a 1,000px table, and the Signal case's argument — one synthetic dataset behind six artifacts, each recomputed from it — has no photographic equivalent that is not a gallery with a paragraph above it. A backend engineer's case needs code, traces and system diagrams at full width; the widest artifact here is a table whose cells are sentences, and the pinned claim beside the scrolling narrative would pin a comment above a diff, asserting a reading order the material does not have. The three case layouts also fail to migrate: they differ because dashboard, generated brief and comparison table differ, and a photographer's three cases would need three framings of images instead, not three argument structures. What survives is the palette and the pill; every structural decision is particular to this material, which is what the direction has to be. Measured, not remembered: `.wrap` is `min(100% - 48px, 1240px)`, so the content column is 1240px at this width and never wider; the radius scale is four tiers — 12px controls, 18px cards, 26px sheets, `999px` pills — and every button and badge takes the same continuous pill, so the page's personality comes from the type and that one decision, not from a different curve per component. Every discrete control is at least 44px tall so the hit area stays stable while the label inside it changes length; the one exception is an inline link inside a sentence, which is 17px and exempt from the rule, underlined instead.

Type is system-only: Georgia/serif for display in English and the system CJK serif for Chinese, `Segoe UI`/`PingFang SC` sans for interface. No `@font-face` ships, so a weight the stack does not carry is synthesised — body text holds at 17.5px (19px in Chinese, where the leading also opens to 1.85), titles keep a clear step, and letter-spacing is switched off for Chinese through `--track-scale` rather than tuned to a second value. The micro and label rungs also run one step larger in Chinese — 15px against 13px — because a CJK glyph fills the same em box with far more strokes: 25 rendered runs measured at 13px before this step, and 15px is where they stopped testing as fine print. One thing a system stack cannot be trusted to do is report its own result: `getComputedStyle` returns the stack as written, while the browser paints whichever installed face happens to cover the glyph. On a machine where "Source Han Serif SC" is registered only as its Heavy instance, a Chinese heading declared `font-weight: 400` painted at 900 and split one line across three families — Source Han Serif SC Heavy for the ideographs, Georgia for the Latin, SimSun for 「」 and →. `--serif` therefore asks for `'Noto Serif SC'` before it, because that family answers the weight that was requested and covers CJK punctuation, so the same heading renders as two matched serifs at every weight from 400 to 700, and falls through unchanged where Noto is absent. This is checked with `CSS.getPlatformFontsForNode`, not by reading the stylesheet. Contrast was computed in the browser over every text run on all eight routes at 1440 and 390, not estimated: 0 failures against WCAG AA, the lowest pair anywhere measuring 4.83:1 (the outcome kicker on its tinted panel) and the home page's lowest 5.97:1.

Motion is hand-written CSS and 3.8 KB of JavaScript — no animation library and no third-party file is fetched at runtime. What the browser really transfers is measured on the wire, not inferred from the markup: home, about, Fieldwork and an unknown id each fetch three modules totalling 28,118 bytes of script (29,018 with response headers); Signal fetches six at 46,606 (48,406 with headers) and Briefly six at 46,252 (48,052 with headers) — Fieldwork and the unknown id never pay for a demo module, because the import is gated on the requested case, and each demo route imports only its own half of the demo code, which is what keeps both under the 60 KB rule. CSS bodies total 59,852 on the routes that need the base layers and 73,303 on the project routes that also load the demo styles (60,452 and 74,203 with headers); every script and CSS figure is identical in both locales, and no response is compressed, because the local server sends no `Content-Encoding`. Nothing that only a build step can use is reachable — the page templates in `tools/views.js` (45 KB) produce the HTML and stop there, and they now sit outside `dist/`, because while they lived inside it the static server answered `/views.js` with the whole file while this paragraph said they never ship; the served tree answers 404 for that path, measured. The example ships no photography, no screenshots and no diagrams-as-images; its media are inline SVG charts and the two working prototypes, so image-ratio handling is demonstrated on the SVG and the data tables rather than on photographs. See `examples/alex-lin/dist/ASSETS.md` for the full asset register.

## Content and navigation

Home: Alex identity and useful-outcome proposition → fictional career context → three compact cases → working approach → about/build-your-own path. Signal shows a synthetic interactive growth dashboard, and its index card carries the case's own weekly totals as a four-bar ledger rather than repeating the hero console; Briefly is an editable deterministic local content workflow; Fieldwork explains product trade-offs with an inspectable concept comparison. Every case includes task, role, artifact/demo, reasoning and limitations. About contains the coherent fictional 2020–2026 timeline, a short capability summary and build notes.

Native `index.html`, `project.html?id=signal|briefly|fieldwork`, `about.html`, and the same three files again under `zh/` — Chinese is a second pre-rendered tree, not a runtime rebuild, so a reader with JavaScript switched off gets the whole written argument in both languages and the switch between them is one link. The directory decides the language; a legacy `?lang=zh|en` on any page redirects to the other tree, carries `id` and the fragment across, and deletes the parameter so a stale bookmark cannot loop. `views.js` — including the two demo mount-point renderers that used to sit inside the shipped `demo-views.js` — runs at build time only and now lives in `tools/`, outside the served tree; `tools/generate-static.mjs` writes all six files from it and `app.js` never imports it. No required preview modal, login, API key or external service. Core artifacts are inline; optional downloads expose the actual synthetic data or sample résumé. The footer carries a `mailto:` as a labelled sample — `alex.lin@example.com`, with "Sample address, not monitored — use your own." directly beside it — because a template that leaves no contact route teaches neither where an address sits in the layout nor how it is written; no invented live integration or real-client endorsement.

## Interaction and responsive behaviour

Use pressure feedback, subtle card tilt, elastic filters and motion pause/reduced-motion. All input/scroll areas remain stationary and touch-friendly. Dashboard market/period controls update actual synthetic chart, table and metrics; forecast assumptions are displayed. Brief input changes actual locally computed output; errors and clipboard failures are visible. English/Chinese locale affects labels, ARIA and number display. Desktop overview has three comparable cards — their artifacts share one 250px image box, so the titles and ratings sit on one line rather than three; mobile stacks them without hiding content. Dense demos reflow rather than shrink text. The charts are inline SVG and keep their viewBox ratio as the column narrows — a chart is data, so it is never stretched to fill a flexible row; the weekly scrub shows one whole frame per step, never a half-cut one. The four static frames are also the whole arrangement below 900px and whenever motion is off, and the Chinese ladder keeps three rungs on a phone (28 / 24 / 20) after a 24px h1 had collapsed into the 24px h2. Mobile menu closes with Escape and returns focus.

## Verification

Check real browser at 1440/2559 wide desktop, 768 tablet and 390/360 mobile; direct case load, both locale trees, filters, native Back, demo math, keyboard, reduced motion, public bundle privacy and root/subdirectory hosting. No route scrolls sideways at 360/390/430, measured on home and about in both locales (scrollWidth 345/375/415 against client widths 360/390/430, and no element extending past the viewport). The hero parallax is verified by measuring distinct transforms on the bezel and insight layers across the scroll, and the weekly scrub by measuring one whole frame per step against the pinned stage — not by watching a recording: five offsets, stage top 0, 0px below the stage, four distinct track positions. A data chart keeps its viewBox ratio in every container: a `preserveAspectRatio="none"` stretch was reverted because filling the flexible row drew the chart's 3:1 viewBox at whatever ratio the row happened to be, and vertical stretch misstates volatility; it now letterboxes at 1158×386 inside that row. Four further checks exist because a claim that is only asserted in a comment is not a claim: the **painted** font of every heading is read with `CSS.getPlatformFontsForNode` (computed style reports the stack as written and hides both a weight substitution and a three-family split inside one line); the smallest rendered glyph is measured after multiplying by the SVG screen CTM, since type drawn in a scaled coordinate system reports a px size that is not what anyone sees; occlusion is asked twice over — the annotation plate is swept against every text leaf on the page at 11 widths × 6 routes × 11 scroll offsets in paint order, with the geometry re-measured at each offset, and separately at rest, where each in-page anchor's landing point is computed from `scroll-padding-top` and `scroll-margin-top` rather than from `scrollIntoView`, which ignores the first; and contrast is computed on the surfaces a component actually sits on — which is how `--focus` on the dark band was found to measure 1.48:1 against the 3:1 WCAG non-text floor, and why focusable controls there switch to `--highlight` at 10.08:1. The occlusion sweep reports its own denominators (812 text runs measured, 0 covered, plus the count of runs that pass under the sticky bar and are not defects) because a check that returns nothing is indistinguishable from a check that ran on nothing. Browser screenshots document the running example; Node tests cover state/math and local server path boundaries. Synthetic career figures, illustrative research and prototype capabilities stay explicitly identified at the point of use.

## Reading paths and depth

Two reading paths share one set of pages: `index.html` presents the three cases as cards inside the hero-and-gallery home, and `project.html?id=signal|briefly|fieldwork` opens one complete case with its prototypes inline; an unknown id renders a missing-case panel that links back to the three real ids. Depth lives in `motion.css` and is attached to named elements, not to the page as a whole. On home, `data-parallax-root` on `.hero-stage` drifts three layers at three rates, all upward and all one-directional: the screen 9px, its bezel 14px, the annotation plate 36px — each read off its measured rest offset (7px and 18px below the card) rather than chosen for feel. The plate used to travel ±54px, and a symmetric excursion reaches 54px *above* the position it was laid out in — straight back over the provenance line the static layout had been fixed to clear. A transform has to be tested where it goes, not where it is arranged. On the Signal case, `.scrub-wrap` is 300vh, its stage is 100vh and sticky, and `animation-range: contain` makes the timeline and the pin the same interval by construction: the wrap covers the viewport exactly while its child is stuck, so every week-step happens on screen. Measured at 1440×900, the stage top stays 0 and the space below it stays 0px at five scroll offsets, the frame is 695px inside the 900px stage, and the 400%-wide track advances exactly one stage-width per quarter. The stepping is `steps(4, jump-none)` while a separate rail fills continuously, so four states read as a scrub rather than a slideshow; the hint sits inside the stage, where a reader entering the pin can see it. Above 900px the pin runs; below it, and with motion off, the same four frames are the static arrangement. Card hover moves `.console-mock`, `.note-front`, `.note-back` and `.brief-bottle` by a few pixels or degrees. Exactly one thing decides whether any of this runs: the `html[data-motion]` attribute, which `motion.js` seeds from `prefers-reduced-motion` and flips with the header pause button, plus one IntersectionObserver that pauses off-screen depth through `data-depth-idle`. `@media (prefers-reduced-motion: …)` is deliberately **not** wrapped around those rules. Gating one decision twice made the two mechanisms disagree, and made the pause control's play half a lie: clicking it set `data-motion="on"` while the media query kept every rule switched off, so a reader who had asked for reduced motion and then changed their mind got a button that reported success and did nothing. `@supports (animation-timeline: view())` still guards the scroll-driven layer, because that is a capability check rather than a preference. The single remaining preference gate is `@view-transition { navigation: auto }`: keying the route cross-fade to the attribute would leave a reader with JavaScript switched off holding a transition they could not decline, since no script runs to set or clear the attribute. There is no CSS3D layer stack, no pointer-driven tilt, no WebGL model and no remote AI service. With motion off, unsupported, or unloaded, every element keeps its static final state and essential text and controls stay usable — verified at 11 viewport widths across the full scroll range, with JavaScript disabled. Two reading paths are an example, not a requirement that other portfolios use two variants.
