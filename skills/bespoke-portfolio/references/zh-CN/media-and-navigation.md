# 媒体、导航与阅读验收

## 图片按读者要看什么来排

- 作品原图与证据截图需要完整时，优先自然比例或 `contain`。封面可为构图裁切，但不能切掉判断作品的关键部分，且完整内容应直接可到达。
- 同一组有横图、竖图、方图时，可用等大舞台居中容纳、按比例网格或有节奏的编排。选择有理由；不要为了整齐把所有原图裁成方形。
- “居中”分开检查：整组容器、图片盒子、原图主体、阅读栏。图片内部留白是原构图的一部分，不能靠无依据放大去掉。
- 不要把竖幅场景图拉成占满屏幕的横向大横幅。将完整图与简明说明并列，或选适合的自然比例更清楚。
- `contain` 与宽高约束一起检查；查看真实计算样式。父级裁切、图片固有尺寸、padding、hover 放大和滚动视差都可能再次藏住图像。
- 默认页面足以读懂。大图链接是可选补充，不让用户必须在新页看图才能知道内容真假。

## 视频、文档与代码

视频提供明确播放/暂停与内容说明；不要自动带声音或依赖观看长视频才知道职责。文档给可读摘要/节选及原件入口。代码项目给运行画面、功能与约束，避免用无关装饰代码冒充实现。

资源失败时有可见替代、有限重试和可用导航；原始内容与 canvas/动画不要因初始化失败一并消失。父级为链接时，避免再嵌入重试按钮等交互元素。

## 入口与出口

- 第一屏：定位、代表内容或清楚概览、主要行动。
- 概览：项目是什么、本人做什么、里面能看到什么。
- 进入：一次明确选择即可阅读完整案例；不先预览再点详情。
- 页内：长内容可有目录，目标出现在固定导航下方。
- 返回：浏览器 Back、返回列表、首页/作品主导航去向一致；相关项目使用具体名称。
- 联系：保持用户决定的公开范围；弹层可关闭、可 Escape、焦点恢复，不靠浏览器后退退出。

## 跨尺寸的读者任务

在用户报告的尺寸和代表性桌面/平板/窄屏实际运行。至少覆盖每种媒体比例、最长标题、混排、真实截图、展开菜单和返回路径。检查：

1. 读者是否知道有哪些项目，并能找到与自己相关的内容。
2. 每张关键图是否完整可辨，数字和截图是否对应；长图是否被强制截断。
3. 标题、正文与数据是否形成清楚顺序；正文行长适合阅读，留白有组织。
4. 点击区域稳定，鼠标在深浅背景都清楚；触屏、键盘和减少动效仍可用。
5. 筛选真的改变结果，选中状态正确；没有差异的筛选要重组或去掉。
6. 返回、目录、重试、关闭和空/错状态都能走通。

没有浏览器时，交付实现和已完成检查，同时说明未验证的部分。布局不溢出、文件存在或语法通过，都不能证明图片没被裁切或阅读体验良好。
