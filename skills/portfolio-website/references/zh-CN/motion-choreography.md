# 动效编排

[深度与奇观](scroll-depth.md) 管的是作品集最多只能挣来的那一个招牌动作。本文件管的是每一作品集其实都在发的那些动效：悬停时的抬起、展开的折页、被筛掉三张又加上五张的过滤器、变成详情页的卡片。几乎全部都被写成十二处 `transition: all .3s ease`，这就是生成出来的页面显得"没有重量"而不是"被设计过"的原因。动效是语法，不是数量：它有持续时间、缓动、次序和方向，每一项都可以有意义，也可以没有意义。本文件不给任何定值。

统摄全篇的一句话是：**移动本身就是信息**。移动的东西告诉读者它从哪里来、要到哪里去；原地变化的东西告诉读者它变了；没有任何过渡就出现的东西，告诉读者页面上凭空长出一个器官。所以每个动画要问的不是"这雅不雅"，而是"读者从这里得到什么，我删掉动画之后他会失去什么"。同一个问题也正是让减少动效那条分支成为另一种论证、而不是一次删减的原因——见下。

## 物件自己的运动说明了一切

| 材料里的条件 | 物件真实的行为 | 页面动效继承什么 |
| --- | --- | --- |
| 散放的纸、卡片、桌上的便签 | 轻、摩擦大、说停就停，绝不过冲 | 时长短、减速强、不用弹性；一张被揭起的纸落回是收住，不是弹回 |
| 泥料、釉、黏滞材料 | 流动、有阻力、缓慢沉降 | 进场长、出场更长、缓动里不许有卡嗒一下的硬停 |
| 对输入即时响应的仪器——表、控制台、键盘 | 几乎瞬时，且数值是连续变化的 | 动效属于指针与读数，不属于面板；界面状态切换不动，数据变化才动 |
| 有装订结构的东西——书、文件夹、钉好的账册 | 绕一条固定的边旋转，一个平面压过另一个 | 有真实 `transform-origin` 的铰链式变换，且折缝处正是光线变化的地方 |
| 联网或计算型工作——队列、构建、推理 | 时长未知，而"未知"正是内容 | 进度表达不能暗示它并不拥有的速度；伪造百分比是对这个人自己的时间撒谎 |

把选中的那一行写进 `DESIGN.md`，与光源那一行同样诚实。材料是钉好的账册、动效却是弹簧卡片物理的页面，是把某个产品界面的肢体语言搬了过来。

**检查。** 读出所有交互态与揭示态上的 `transition` 与 `animation` 声明。逐条在 `DESIGN.md` 里点名它主张的是材料的哪个属性。没有主张的声明，以及与上表那一行冲突的主张，就是结论。

## 时长来自位移，不来自令牌

40px 的标签和 60vw 的面板共用一个时长，是同时的两处缺陷：标签像被打了一针，面板像出了故障。感知时长随移动距离与物件尺寸变化，而读者判断的是比值不是数值。所以每个时长按它承担的那段位移推出来，只保留一个共享常数作为*参照*位移——页面用得最多的那个距离，其余一切都比它更长或更短。

然后用这个比值来表态：读者应当感到是页面中心行为的那次过渡，拿到全页最长的时长；不该被注意到的那件拿到最短的。如果全页最大的位移与一次悬停耗时相同，那么这个页面已经决定没有任何东西是重要的。

**检查。** 收集实际生效的各个不同时长，以及每个时长承担的那段位移（两态之间 `getBoundingClientRect` 的差）。合格要求时长随位移单调递增——不必线性，但要严格到没有一次 4px 的微移比一次整屏揭示更久。然后报告页面一共用了几个不同时长：一个说明没有语法，多到七八个以上说明尺度已经成了装饰。

## 缓动是一句关于物理的陈述

`ease` 不是中立选择；它是一条轻微的先加速后刹车曲线，什么都不特别合适，因此被读成"默认值"。真正带意义的有四条：

- **减速到位**（ease-out 一族）用于任何进场，因为它带着速度进入读者注意力所在，又在他要读的位置稳稳收住。
- **加速离开**（ease-in 一族）用于任何出场，因为出场的头几帧没人需要，而最后几帧才告诉他东西去了哪里。
- **对称**用于原地变化，因为它根本不在移动，非对称曲线会凭空造出一段旅程。
- **线性**只用于真正连续的东西——沿时间的擦洗、旋转件、跑马灯——凡是会启动和停止的都绝不能用它，因为线性停止是一次撞击。

过冲与弹簧是关于弹性的主张。纸不过冲；硬封皮不弹。只有材料里确实存在会回弹的东西时才允许，而且要小到读起来是物件自己的质量，而不是某个动画库的默认值。

**检查。** 对每一对动画状态，读出缓动函数并把运动归类为进场、出场、原地变化、连续。合格要求进场减速、出场加速；每一条声明都落在同一个曲线上的页面是 fail——包括全是 `ease` 和全是 `linear`——因为那时缓动不携带任何信息，删掉也没有损失，而"删掉无损失"正是它当初没被设计过的证明。

## 进场快、出场慢，且永远不要同时

对称的进出是未声明动效最可靠的破绽。非对称很便宜，而且会被读成意图，因为真实事物被注意到的是到来，被记住的是离开。按读者需要什么逐个元素决定：由他**召唤**出来的（菜单、搜索框、刚应用的筛选）应当进场快于出场，因为他已经知道自己要什么，正等着读；**打断**他的（提示、报错、确认）应当进场慢于出场，因为到来本身就是消息，而关掉它不是。

所有人都忘掉的那一例是从网格里删东西。过滤器拿走三张卡片、重新摆放五张时，一次没有错峰、没有过渡的重排是不可读的——读者分不清哪些是留下来的。这正是共享元素或 first/last 位移变换唯一挣到成本的地方：穿过变化而活下来的那件，必须被看见还是同一件。

**检查。** 对每个开态与闭态都有动画的元素，比较两个时长并报告哪个更长。高于一个控件的元素上出现等长对，就是结论。然后触发一次会重排内容的筛选或切换，确认至少有一个存活元素是从旧位置动画到新位置而不是瞬移；如果没有任何东西可见地存活下来，那么这个页面在一次交互之后就无法被扫读。

## 只有当次序就是论证时才错峰

整列统一按序号递延的级联是生成式动效的签名，而且错两次。第一，读者快速滚动时它让页面像屏保，还把最后一项的可读时间推迟了整个级联的长度——第五张卡片为了陪衬第四张的"编排感"而迟半秒出现。第二，也更糟：**它给次序本身就是数据的内容强加了一段次序**。排名表、按日期排列的时间线、榜单、变更日志：序列就是数据，把序列做成视觉级联等于说"它们是一件件到达的"，既不真也不是读者需要的。

错峰诚实的时候，是容器的排布本身正在被介绍——需要看见"整组"的展示墙、互不相关的标本网格、从触发点展开的导航。此时轴向要紧：按行读的网格应当按行错峰；沿列级联一个行优先的网格，会发明出页面并不拥有的次序。

**检查。** 找出所有由序号推出的 `transition-delay` / `animation-delay`。逐个报告容器的排布方向、子元素个数、以及落在最后一个子元素上的延迟。容器是排名或时间序的就 fail（由标签、说明或 `DESIGN.md` 指明是哪一种）；最后一个子元素等待到能被察觉成"在等"就 fail；级联轴与阅读轴不一致也 fail。零错峰的页面不是 fail——那常常正是推导出来的答案。

## 合成、绘制、布局——以及为什么它在悬停处咬人

三档代价，差别在中端手机的 390px 屏幕上绝非学术：

- `transform` 与 `opacity` 走合成层：浏览器移动已经画好的一张图层。
- `background-color`、`color`、`box-shadow`、`filter` 强制重绘；`backdrop-filter` 和大面积 `filter` 会把它们后面的一切一起重绘。
- `width`、`height`、`top`、`left`、`margin`、`padding`、`font-size`、`line-height` 强制布局，而布局会沿树递归——动画折页的 `height` 就是每帧重排它下面的所有元素。

所以：变换换与不透明度；小型局部状态变化可以接受绘制档；任何布局属性都绝不放进悬停过渡，因为悬停会被快速反复触发，第二次到来时第一次还在排版。`height: auto` 无法插值，这就是传统手风琴动画到一个魔法数字然后在末尾一跳的原因——改用 grid-row 或 `scale` 那两种做法之一，并写明用了哪种。

`transition: all` 是把这一切都藏起来的那个 bug，因为它会悄悄接住断点处的 `font-size`、文案变长时的 `width`，以及别的什么东西设上的 `transform`。把属性列出来。

**检查。** 解析每一条 `transition` 与 `animation` 的属性清单。已发布 CSS 中任何位置的 `all` 都 fail。任何 `:hover`、`:focus`、`:active` 规则里出现布局档属性都 fail。然后实测：滚到底、滚回顶、打开最大的折页，同时采集帧间隔——在桌面视口上就掉帧的页面，一定在评审者真正使用的那台手机上掉得更厉害。

## 减少动效是同一个论证，换一种讲法

`prefers-reduced-motion: reduce` 不是"页面的扁平版"。这个偏好的存在，主要是因为*运动本身*对某些人是难受或令人眩晕的——而删掉一个动画就删掉了它承载的信息，那只是换了一件衣服的同样内容损失。所以每个动效都要决定它当时在讲什么，然后留下那部分：

| 这段动效承载的东西 | 减少动效分支仍必须做到的事 |
| --- | --- |
| 某物从哪里来（菜单、面板、路由） | 立刻把它放到那里。出现次序不是必需，最终位置正确是必需 |
| 某物变了（状态、数值、选中） | 不做插值地原地改变，并让新状态自己可读——读者不必看见过渡也能知道发生了事 |
| 他刚操作的是哪一项 | 保留高亮，去掉行程 |
| 作为内容的序列（擦洗、时间线揭示） | 一次性静态呈现完整序列并保持可读——这是难的一例，把它塌回第一帧是内容损失，不是无障碍收益 |
| 纯粹装饰 | 删掉。只有这一行，删除是正确答案 |

真正会毁掉交付的那个陷阱：内容起手是 `opacity: 0`，靠动画或滚动观察器揭示。减少动效时动画被关掉，揭示永不发生，于是那段文字不存在。这不是视觉缺陷，是内容缺失，而且它在默认分支的截图里完全看不见。

**检查。** 用强制 `reduce` 的仿真加载页面，然后：枚举每一个计算 `opacity` 为 0、或盒子被 `transform` 顶在视口之外的元素，确认该状态下没有任何文字、图像或控件是不可达的。确认减少动效的分支存在，且覆盖了滚动驱动与交互驱动的动效（而不只是 CSS 关键帧），确认没有靠 `!important` 去抢输赢，并确认想要动效**开着**的读者那个开关仍然有效且能记住。然后对每条路由在两种模式下各取一张静止截图对比：任何一条路由在两者之间内容不同就是 fail，因为无障碍应当改变页面怎么动，不应当改变它在说什么。

## 顺序

先修状态，再修动效——见[交互状态](interaction-states.md)：一次改变高度的悬停需要有可以变进去的阴影结构，一次按压需要有可以对照测量的通道。先修空间层级与重叠，再修动效——见[空间构造](spatial-construction.md)——因为一个动画中的浮层会穿过页面也许并未声明的层级，而一段 transform 能在每个循环里把一次静态碰撞重新制造出来。招牌动作最后才选，从[深度与奇观](scroll-depth.md) 里选，这样景观继承其余一切服从的时长、缓动与减少动效规则，而不是变成另一套自带词汇表的物理系统。
