# 交互状态

一个部件的每个可能状态都被设计过，它才算完成。生成出来的产出通常只做了静态与悬停，然后称这个按钮做好了——缺掉的状态正是作品集显出半成品感的地方，也正是真实读者卡住的地方。用户抱怨"缺少高级的微交互与按下反馈"，几乎从来不是动效质量问题，而是有些状态根本不存在，以及按下时页面没有可测量的位移。

下面每条机制都配一个脚本或审查者能在构建页面上算出来的检查。观察不到的状态，就是没做出来的状态。

## 完整性清单

页面里每一个可交互对象——链接、按钮、可跳转的卡片、筛选器、开关、输入框、折叠面板——都欠八个状态。

| 状态 | 它回答的问题 | 生成产出通常的样子 |
| --- | --- | --- |
| 静止 | 这是什么，它能点吗？ | 正常，而且往往是唯一做出来的状态 |
| 悬停 | 我指中了它，点了会发生什么？ | 一处来路不明的变色，或者什么都没有 |
| `focus-visible` | 同样的问题给键盘读者，而且没有指针 | 规则只写在 `button` 上，于是链接、卡片、标签永远不会出现 |
| `active`／按下 | 我这次输入被接住了吗？ | 缺失，或者一条读者早已不信的 300ms 过渡 |
| 加载 | 有事在发生吗，结果会出现在哪里？ | 给一个本来就没有异步路径的内容挂转圈，或者毫无提示 |
| 禁用 | 现在不能操作，为什么？ | 只改 `opacity`，于是对比度不达标，而且元素从命中测试里消失 |
| 空 | 什么都没匹配上——接下来怎么办？ | 直接删掉整个分区，读者无法区分筛错了和页面坏了 |
| 错误 | 出了什么事，怎么恢复？ | 从未被构建，因为页面上没有任何东西可能失败 |

加载、空、禁用、错误这四项被跳过只有一个原因：构建出来的页面里没有任何路径会走到它们。办法是主动制造条件——筛到一个不匹配的值、断网加载、请求一份从未附上的文件——然后去看那一屏。一个没有可达路径的状态不是设计决定，是缺口。

八种状态属于上面点名的那些对象，不属于每一个技术上能匹配上伪类的节点。逼一个滚动容器交出悬停和按下，奖励的恰恰是错误的东西——往地标上贴一次换色；而这个容器真正欠的是"这里能滚"的线索。所以先读归属列，再看矩阵：

| 对象 | 欠的状态 | 不欠 | 原因 |
| --- | --- | --- | --- |
| 链接——包括导航、页眉、页脚的链接，以及整个列表项就是链接的情况——按钮、会跳转的卡片、筛选器、开关、折叠面板、标签页 | 它这条路径能到达的全部八种 | — | 它是读者瞄准的目标，对方的每一次输入都是对它的一次表态 |
| 行文中的链接：同一个 `p`、`dd`、`blockquote`、`li`、`td` 里，它前后还有文字 | 悬停、`focus-visible`、按下——以文字本身的变化呈现：色调、下划线、字重 | 按下位移 | 句子里的一个词是被读的，不是被瞄准的；让它位移会让这一行重排，整段文字随之漂动 |
| 文本输入框与 textarea | 静止、`focus-visible`、禁用、错误、加载（若能异步校验） | 悬停、按下 | 光标和选区就是按下的回应；本来就像输入框的字段再加一层悬停只是装饰 |
| 原生 `select`，以及任何由平台绘制外观的控件 | `focus-visible`、禁用、展开（若它暴露展开） | 悬停、按下 | 平台把这两种画在封闭的 shadow tree 里，作者样式表没有对应规则并不能证明屏幕上什么都没变 |
| 滚动区域（`[role=region]`、`overflow` 容器、轮播视口） | 静止、键盘可达时的 `focus-visible`、可容纳为空时的空态，以及一条"后面还有内容"的静态线索 | 悬停、按下、禁用 | 它是内容的窗户，不是靶子；见[部件解剖](component-anatomy.md)的表格适配规则 |
| 没有处理器的装饰元素 | — | 全部 | 它没有状态；一旦需要状态，它就是控件，归第一行 |

文档本身已经声明为导航的区域——`nav`、`[role=navigation]`、`[role=menu]`、`[role=menubar]`、`[role=tablist]`——在标签之前就把问题定下来了。放在里面的链接即使和其他链接并排待在 `li` 里，也是被瞄准的目标，行文豁免到不了它；页眉里独自站着的字标和联系链接同理。豁免跟的是句子，不是元素。

**检查。** 按角色枚举渲染 DOM 中的可交互元素（link、button、switch、textbox、combobox，以及任何带点击处理或 `role` 的元素），然后只对该类型*欠*的那一列判断是否存在一条会在该状态下改变可见属性的规则——在真实条件下读取解析后的样式：悬停用真实指针移动，`:focus-visible` 用键盘，`[aria-disabled]`、`[aria-busy]`、`[aria-expanded]` 用属性，空态与错误态用它们各自的渲染路径。输出"元素类型 × 状态"矩阵，凡该类型确实欠着的状态这一格为空即不通过。仪器够不到的格子记为"不可测"，绝记为通过。规则只打在 `button` 上的页面，对每一种链接和卡片都是失败的。

**检查。** 对每一个能进入加载、禁用或空态的元素，记录状态变化前后的盒子。通过要求盒子完全一致：会引起重排的状态读者无法预判，而跳动正是筛选器看起来像坏掉的原因。

## 什么让一个状态显得没做完

五条审查者一眼就能看出来、而且都能测量的现象：

- **只有颜色在变。** 没有第二通道——边、层次、字重、位移——的状态在灰度下不可见，对色盲读者也不可见。与[视觉验收](visual-review.md)里"层级不依赖颜色"是同一个缺陷。
- **变化量小于"静止与这个状态之间的差别本身"。** 悬停把边框提亮几个百分点，读起来像渲染故障。台阶必须超过读者在该表面上能察觉变化的水平。
- **没有退回路径。** 指针离开后悬停仍在、失焦后焦点环还在、`pointercancel` 或失焦后缩放不复位。测法是把指针移出窗口，而不是移到另一个元素上。
- **过渡时长与该状态存在的时间不匹配。** 按下反馈用入场动画的长度就是延迟；入场用按下的长度就是一张永远静不下来的页面。
- **点击区在动。** 任何改变目标自身尺寸或位置的状态——内边距、边框增宽、外层盒子缩放——都会让元素躲开光标。参见[视觉方向](visual-direction.md)关于倾斜的说明：只允许内层移动。

**检查。** 对每种交互类型，在静止与其能进入的每个状态下读取计算盒子与命中区矩形。通过要求：命中区矩形在所有状态下逐字节一致；悬停与 `focus-visible` 各自至少改变一个非颜色属性；该状态自身属性的过渡时长落在[视觉方向](visual-direction.md)动效表的按下／入场区间内。

## 从材料推导按下反馈

位移不是一个要挑的常数，而是关于"这个物件是什么做的"的一句主张。问：在控件这个尺度上，拇指压下去时材料会发生什么，让答案决定三件事——它到底动不动、只变形状还是变明暗、以及它怎么回来。

- **纸与印刷物**——纸不会被压扁。它用明暗和边缘回答：表面略沉、细线读起来更硬、任何移动都只是边角翘起而不是整块偏移。回复立即且精确，因为纸不记得被按过。
- **玻璃与釉面陶瓷**——刚性，没有行程。响应是一次极小的等比缩放加上一条被提亮的边，回复很快且没有回弹，因为没有任何东西被弯曲。
- **金属与硬珐琅**——带段落感的控件。它沿光线方向走很小一段，接触阴影随着压紧而收紧，回复不弹。可见线索是阴影合拢，不是形状缩小。
- **黏土、橡胶等软物**——在接触点局部变形而非整体缩放：位移是局部的、不对称的、边缘鼓起，回复带一次小小的沉降。只有材料确实是软的才可以用；一个软件作品集弹出橡胶感，是借来的人格。
- **屏幕与示意图**——没有可压的表面。反馈就是状态变化加上光标或选中线索，任何模拟的挤压都在对物件说谎。

位移量按控件自身高度的比例推导，时序按该材料的响应在视觉上有多快推导——硬的东西一两帧内答完，软的东西要几帧。然后全站所有控件用同一个隐喻：纸按钮旁边放一个橡胶卡片，是一张桌子上两种材料。

**检查。** 在无头浏览器里取一个代表控件，记录静止时的计算 `transform`，派发真实 pointer-down，等这个元素自己声明的过渡停止移动之后再记按住值（绝不在过渡的第一帧就取），然后释放并在回位后记一次。报告矩阵差值（平移像素、缩放系数）、还变化了哪些它欠的通道，以及回到原状所需时间。通过要求：每一种可按下类型都至少在它欠的一个通道上有非零差值——材料给出的答案是位移时走仅合成的属性，材料说这个物体不位移时走色调或边缘，因为一张纸按钮变暗就已经回答了，此时再要求它有 transform 与上面的材料论自相矛盾；在[视觉方向](visual-direction.md)的按下区间内回到静止矩阵或静止色调；若存在位移，其差值只占控件高度很小的一小部分，以保证文字仍可读、不漂；前后命中区矩形一致。然后横向比较各控件类型——纸和玻璃位移完全相同，说明用的是一份配方而不是一次推导。

## 指针跟随、吸附、滚动条显形

三个小机制承担了大部分所谓"高级感"，各自有一个职责，也各自有一条下限。

- **指针跟随**（高亮、边缘光或光斑随光标在表面上移动）回答"我在这个大物件的哪一块"。它必须被限制在物件内部、不得移动物件或其命中区、静止态不能是硬复位，触屏上必须退化为"没有"而不是退化为"卡住的光"。物件本身很小的时候，跟随就是装饰。
- **吸附**（滑块、分段胶囊、磁性目标落到离散位置）说明控件有真实的状态而不是连续量。它必须跟随*被选中*的项而不是最后悬停的项，并且在动效关闭时位置依旧正确。
- **滚动条显形**（只在还有内容可读时出现轨道或边缘）是任何滚动区唯一诚实的可供性提示，也是组件无法完整展示内容时唯一可接受的答案。它还需要一个静态线索——边缘渐隐、被切断的样子、下一项露出的一个碎片——因为只在拖动时出现的滚动条对键盘读者不可见，而毫无线索的滚动区就是[组件解剖](component-anatomy.md)里记录的那个缺陷。

**检查。** 指针跟随：在物件内取四个位置，断言高亮随之移动、始终留在物件盒内、且物件自身矩形不变。吸附：分别用键盘和点击驱动选择，断言指示器矩形等于被选项的矩形，两种输入、动效关闭时都成立。对 390 宽度下 `scrollWidth` 大于其可视宽度的每个元素，断言至少存在一种显形线索；只有在本平台恰好画出了原生滚动条时才通过的滚动区，在触屏上就是失败。

## 可访问名称与对外暴露的状态必须一致

一个真实发布过的缺陷值得写成规则：一个动效开关在页面已经暂停时仍然宣布 "Play page motion" 且 `aria-pressed="true"`。名字说的是动作，状态说的是相反的事实，读屏用户无从判断按下会发生什么。本文件所有检查它都能通过，因为视觉状态是做出来的。

把两件事分开，不许混：可访问**名称**描述对象（"页面动效"），状态**属性**描述它对当前世界做了什么（`aria-pressed`、`aria-expanded`、`aria-checked`、`aria-selected`、`aria-busy`、`aria-disabled`）。如果你坚持把动作写进名称（"播放页面动效"），那么名称必须随状态一起变，检查方式不变。状态反向比状态缺失更糟：缺失让读者猜，反向让读者自信地错。

**检查。** 对每个开关、折叠面板、标签页、可选中控件：读取可访问名称与全部状态属性，用真实点击激活一次，再用键盘激活一次，各重新读取。通过要求：状态属性确实翻转；名称在描述对象时保持稳定，在描述动作时改成反向动词；名称与可见标签不矛盾；视觉状态与对外暴露的状态描述同一件事——为每个状态属性至少断言一个可观察的视觉属性，于是 `aria-pressed="true"` 渲染出与 `false` 相同像素的情况，即使属性技术上正确，也要判失败。

## 顺序

先给归属表第一行的每一种对象做静止、悬停、`focus-visible`、按下，因为它们现在就摆在页面上。然后制造条件，把加载、空、禁用、错误这四屏真的做出来。再从材料推导按下反馈。表面要先于状态修——见[表面、光与层次](surfaces.md)——因为没有阴影结构可切换的"层次变化"，只是一次换色穿了个名字。
