# 媒体、导航与阅读验收

## 图片按读者要看什么来排

- 作品原图与证据截图需要完整时，优先自然比例或 `contain`。封面可为构图裁切，但不能切掉判断作品的关键部分，且完整内容应直接可到达。
- 同一组有横图、竖图、方图时，可用等大舞台居中容纳、按比例网格或有节奏的编排。选择有理由；不要为了整齐把所有原图裁成方形。
- “居中”分开检查：整组容器、图片盒子、原图主体、阅读栏。图片内部留白是原构图的一部分，不能靠无依据放大去掉。
- 不要把竖幅场景图拉成占满屏幕的横向大横幅。将完整图与简明说明并列，或选适合的自然比例更清楚。
- `contain` 与宽高约束一起检查；查看真实计算样式。父级裁切、图片固有尺寸、padding、hover 放大和滚动视差都可能再次藏住图像。
- 默认页面足以读懂。大图链接是可选补充，不让用户必须在新页看图才能知道内容真假。

## 视频、文档与代码

视频提供明确播放/暂停与内容说明；不要自动带声音或依赖观看长视频才知道职责。文档给可读摘要/节选及原件入口。代码项目给运行画面、功能与约束，避免用无关装饰代码冒充实现。

资源失败时有可见替代、有限重试和可用导航；原始内容与 canvas/动画不要因初始化失败一并消失。父级为链接时，避免再嵌入重试按钮等交互元素。

## 从图片里取出一个颜色

[视觉方向](visual-direction.md) 要求每个强调色写明它采自哪个文件、哪个位置。这条要求很容易被敷衍，所以步骤比规则更重要：

不要对图片取平均。几乎任何照片或扫描件的平均色都是一团低彩度的泥，用它涂出来的页面死气沉沉，却算遵守了规则。正确做法是：只收集离灰、离黑、离白足够远、确实持有颜色意见的像素，做色相直方图，然后读出属于**物件**而不是背景的那一簇——一只灰布上的青瓷碗的照片有两个簇，而像素更多的那个是布。

采用之前先验证：把它放到页面真正使用的底色上量对比度。一个在正文字号下过不了 4.5:1 的采样色，是装饰色或大数字色，不是强调色；在 `DESIGN.md` 里如实写明这一点，比悄悄把它加饱和直到过关要好。记录文件、坐标或具名区域、色相，以及对比度结果。

有时诚实的答案是材料里根本没有颜色：黑白印件、终端、电子表格。采样后只找到中性色，那就从**地面**推导调色板——纸、墨、格线——并把强调色的职责交给结构性的东西，例如唯一的一个状态色，且写明它在标记什么。找不到色相是一个结论；不要编一个，也不要退回[一眼是生成的](reads-as-generated.md) 所点名的"暖纸加土红"默认值。

**检查。** 确认 `DESIGN.md` 里每个强调色都带着文件名与采样点，采样点落在被引用图片真实的像素尺寸之内，且所记色相与最终令牌在很小的角度差内一致——而不是另一个颜色配上一条引用。再确认该强调色在它被使用的字号上通过它自己声明的用途。一条与所引像素不符的出处行，比没有出处行更糟，因为它看起来已被验证过。

## 没有照片的时候

没有图像是很常见且完全正当的状态——工作是代码、是文字、是一个数量，或者涉密。但这不是引入库存照片或生成替身的许可：一张没有发生过的照片是关于这个人工作的陈述，而读者分辨不出来。下面五种替代按它们保真程度排序，本来能用靠前的却用了靠后的，就是缺陷：

1. 把作品本身作为数据：那张图、那个 diff、那张表、那段日志、那份规格单，用页面自己的物件渲染出来。这就是工作*本身*，不需要相机。
2. 把作品本身作为文字：那段散文、那首诗、那个条款、那条界面字符串，按它真实的比例与真实的换行排成一个绘制对象。
3. 按度量绘制的图形：剖面、正交投、爆炸装配，用这个人自己的尺寸绘制并标注。写明它是画的。
4. 从真实物件上采到的颜色或材质样板，并写明采样点。
5. 什么都没有——页面说明这件工作无法展示、为什么无法展示，并给读者一个可以开口要的入口。这是一个完整的答案，也比伪造好；确实有作品集完全以此方式做成。

在物件自己身上、用读者的语言，标注你用了第几种。一张被误读成照片的手绘图，比一块空白更损害这个人的可信度。

**检查。** 对页面上每个图像位置，确认它装的是真实工件、真实渲染，或被明说的替代物，且明说的种类与渲染出来的东西一致——画的要标为画的、图里的数字要能追溯到来源、缺席的图要在它旁边的文字里被承认。任何既不是此人材料、也不是工作记录的位图都 fail，任何生成的替身一律 fail，无论它是否被标注。若整站一张照片都没有，确认第一屏上仍然有**作品**，而不是关于作品的标题。

## 媒体的代价

图像多的作品集，是在评审实际使用的那条网络上失败，而不是在作者自己那条上。每个位图都要有固有尺寸，好让加载时它下方的文字不跳动；读者第一眼看到的那张图按它将要被绘制的尺寸获取，而不是从相机原件缩放；折叠线以下的图不与它争抢带宽；而一个画出来的物件同样用这些单位计量——一张几千条路径的 900px SVG 一样贵。

**检查。** 报告每条路由上最大的图其字节数对照它实际渲染进的盒子，并标记任何交付宽度超过约为绘制宽度两倍的图。确认首屏一切元素预留了尺寸，然后在限速配置下加载并报告图片到达时是否有文字移动。确认加上媒体之后 [视觉方向](visual-direction.md) 的字节预算仍然成立，因为媒体正是一个纯文字时达标的页面悄悄超预算的方式。

## 入口与出口

- 第一屏：定位、代表内容或清楚概览、主要行动。
- 概览：项目是什么、本人做什么、里面能看到什么。
- 进入：一次明确选择即可阅读完整案例；不先预览再点详情。
- 页内：长内容可有目录，目标出现在固定导航下方。
- 返回：浏览器 Back、返回列表、首页/作品主导航去向一致；相关项目使用具体名称。
- 联系：保持用户决定的公开范围；弹层可关闭、可 Escape、焦点恢复，不靠浏览器后退退出。

## 跨尺寸的读者任务

在用户报告的尺寸和代表性桌面/平板/窄屏实际运行。至少覆盖每种媒体比例、最长标题、混排、真实截图、展开菜单和返回路径。检查：

1. 读者是否知道有哪些项目，并能找到与自己相关的内容。
2. 每张关键图是否完整可辨，数字和截图是否对应；长图是否被强制截断。
3. 标题、正文与数据是否形成清楚顺序；正文行长适合阅读，留白有组织。
4. 点击区域稳定，鼠标在深浅背景都清楚；触屏、键盘和减少动效仍可用。
5. 筛选真的改变结果，选中状态正确；没有差异的筛选要重组或去掉。
6. 返回、目录、重试、关闭和空/错状态都能走通。

没有浏览器时，交付实现和已完成检查，同时说明未验证的部分。布局不溢出、文件存在或语法通过，都不能证明图片没被裁切或阅读体验良好。
