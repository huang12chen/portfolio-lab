# 视觉验收

从源码判断作品集会漏掉大部分真正重要的东西。版式、对比度、字体回退、动效节奏、裁切，只有在页面渲染出来之后才存在。必须看渲染结果，而且要看多个宽度，才能说做完了。

[English version](../visual-review.md)

## 记录你真正看过什么

记下浏览器、测试过的宽度、实际操作过哪些交互。无法渲染时，明确说明未验证的范围，不要暗示做过检查。靠读 CSS 得出"响应式良好"不算检查。

## 通过 / 不通过清单

每一条都有可观察的答案。如果一条检查无法从截图或计算值判定，它就不属于这里。最值得盯住的，是那些完全不报错的问题：未定义的自定义属性、静默回退的字体、被量了两遍的留白、被手改过的生成页——它们看起来都是完成状态，行为却是错的，所以每一条检查都必须去读渲染出来的值，而不是读源码。

| 检查项 | 怎么做 | 通过标准 |
| --- | --- | --- |
| 推导有记录，不是自称 | 查 `DESIGN.md` 里的实测属性和强调色的出处行 | 宽高比、取样主色、结构层数、密度、时序还是空间、有无肌理，都是对着真实文件量出来的；每个强调色都写明来自哪个文件的哪个位置 |
| 版式原型互斥 | 把首屏对照[视觉方向](visual-direction.md)里七个签名物件 | 选中的那个在场，其余一个都不出现；两个人的站点之间，两个强调色相距约十五度色相以上 |
| 参考配得上它自称的深度 | 拿 `DESIGN.md` 里每条参考的状态词，与它旁边的观察逐条对照 | 凡是声称 `interaction-tested` 的行为，都带着一个数字或一次状态变化。只靠名字、灵感库缩略图、200 响应或形容词支撑的条目，一律降到实际到达的深度 |
| 每屏一个视觉重心 | 眯眼或模糊页面，直到文字不可读 | 一个主导区域；或者一条主张连同紧邻它、读起来属于同一组的证据。两个互相争夺注意力的主张，或一个都没有，说明层级没有撑住 |
| 层级不依赖颜色 | 把截图转成灰度 | 阅读顺序和分组依然清楚；如果只有强调色在区分它们，那是对比度在替颜色干活 |
| 声明的字体就是渲染的字体 | 读取标题、正文、以及一处中文文本的计算 `font-family` 和 `font-size` | 出现的是预期字族；静默回退属于缺陷，不是偏好 |
| 行长与行高成立 | 在 1440 和 390 分别数字符数 | 两个宽度都落在[视觉方向](visual-direction.md)给的区间内 |
| 手机端标题没有被等比带过去 | 在 1440 和 360 读取最大标题的计算 `font-size`，并数它折成几行 | 宽度下降时标题与正文的倍数本身要缩小，标题大致两行以内收住。用 `clamp()` 或相对单位维持桌面倍数，落到手机上照样过重 |
| 标点只出现在正文里 | 逐个读标题、导航项、标签、按钮、徽标、数值、单行图注的最后一个字符——**而且要读它们内部每一段的最后一个字符**，因为写成 `第一行。<br>第二行` 的标题，它的句号会躲过只查结尾的探针；而真正在承担标题职责的元素，常常是一个被加了样式的 `<p>`；最后再搜正文之外的装饰性 `·`／`～`／`！` | 这些角色都不以 `。！？，、` 收尾，数据单元格里没有拖尾句号。标题里承担对偶句法的逗号与冒号要留着——删掉它们制造的是不通的中文，比原本要修的毛病更糟。正文保留标点；单位约定全站一种，引号每种语言一种写法 |
| 间距节奏出自同一套系统 | 抽查若干组内间距与组间间距 | 组内明显小于组间；两者接近，就等于把排序工作丢给了读者 |
| 没有裁切与溢出 | 在 360、390、768、1440 以及读者报过的宽度各截整页 | 无横向滚动、无标签截断、无产物被裁 |
| 对比度经过计算 | 用文字真正所在的底色实测，包括带色面板上的弱色文字和小号字距标签 | 正文 4.5:1，大字与图形 3:1 |
| 状态齐全 | 悬停、Tab 聚焦、按下、禁用、加载、空态 | 每个都像被设计过，且都不引起布局跳动 |
| 表面、状态完整性与部件解剖各有对应探针 | 不要目测，逐条去跑那些文件里写明的可测量检查：[表面、光与层次](surfaces.md)里抬起元素的计算 `box-shadow` 层数与各层偏移与模糊之比；[交互状态](interaction-states.md)里的"可交互类型 × 状态"矩阵，以及静止与按下之间的 `transform` 差值；[组件解剖](component-anatomy.md)里兄弟操作链接的 `top` 差值、本页 `h1` 对最大 `h2`、每张表的宽度对容器及其提示 | 每条探针留下一个数字，不是形容词。抬起元素具备记录光源所推出的层结构与内边；某类型能够进入的状态一格不缺且名称一致；必需部件没有缺失，读者纵向扫描的那条基线没有漂移 |
| 控件几何是被决定的 | 读取主按钮、次按钮、输入框、标签、卡片的计算 `border-radius`，并和控件自身高度对比 | 两到三个值构成一个家族，在 `DESIGN.md` 里给出源自材料的理由，嵌套圆角由容器推导。44px 的目标上挂着 2–4px 圆角，那是框架默认值还留在原地；胶囊主按钮旁边立着直角按钮，就是两套系统 |
| 状态规则不改变控件形状 | 每种控件都用 Tab 聚焦一次，记录聚焦前后计算出的 `border-radius` | 聚焦只画焦点环，不改形状。全局 `:focus-visible` 规则里写了几何属性，优先级就会盖过组件自身的类，于是胶囊按钮在被键盘选中的那一刻变成直角方块——鼠标用户看不见，截图里也拍不到 |
| 一个量出来的事实只住一处 | 找出样式表里重复出现的每个数字——页头高度、sticky 的 `top`、抽屉的 `top`、滚动留白——再逐个跳转页内锚点，量目标落在 sticky 栏下方多远 | 只有一处声明，其余全部由 `calc()` 从它推导，而且每个断点上的落点净空一致。两套留白机制叠在一起就是多了一套；而一份悄悄过期的副本，正是单一声明存在的意义 |
| 自定义属性在真正加载它的页面上成立 | 收集所有样式表里的每个 `var(--x)` 引用和每个 `--x:` 声明，两个集合相减，再在使用该名字的元素上读取计算值 | 每个引用都能在该页面真正取到的样式集合里找到声明。未定义的自定义属性是 guaranteed-invalid value：整条声明被丢弃，控制台一句话都不说，所以一次漏改十二处的重命名照样渲染得像毫无问题 |
| 动效有目的且有退路 | 慢速滚动一次，再开 `prefers-reduced-motion` 滚动一次 | 每个动画都在教东西；降级路径能读到同样内容；暂停控件真的拆掉特效。若系统已请求减少动效就把开关置为不可用，等于恰恰从最需要把它要回来的人手里夺走选择 |
| 动效是机制，不是配方 | 对页面上每个特效，用一句话说清：什么输入触发它、哪个属性在变、它回到什么状态、触屏或键盘读者拿到什么 | 描述里不出现任何库名或预设名。倾斜只动内层、点击区不动；计数器最终落在真实数字上；共享元素不留下重复导航。一个只能靠包名来描述的特效，是贴上去的，不是设计出来的 |
| 语义有效而非装饰 | 数每页 `h1`、找跳级、确认 `footer` 在 `main` 之外、检查每组 `dt`/`dd` 都包在 `dl` 里 | 每页一个 `h1`；不跳级；contentinfo 暴露。用带样式的 `<p>` 充当页面标题、还用 `aria-labelledby` 指过去，那是缺失的标题，不是设计选择 |
| 表格能被机器读懂 | 逐个 `th` 查 `scope`，逐张表查 `caption`；在 390 宽度量每张表的实际宽度 | 表头与单元格关联成立；表头没有因 `white-space:nowrap` 把表撑到视口两倍宽、塞进无提示的滚动容器。被裁掉那一列往往正是承载论点的那一列 |
| 小字是量出来的，不是假设的 | 读取页面上最小渲染字号的计算值——乘上各自的屏幕 CTM，因为缩放后的 SVG 里图表文字会比属性写的小——以及它的颜色相对其真实底色的对比，再加上一段正文的计算字号 | 不低于约 11px；正文落在[视觉方向](visual-direction.md)给的区间内——15px 的中文段落即便整页刻意做密，也仍是违规；那个被用于所有标签的弱色 token 在带色面板上同样过 4.5:1。token 区若写了比值就重算一遍——注释里未核实的数字，是一个带着多余自信的缺陷 |
| 焦点路径完整 | 从第一个元素开始 Tab，跟随跳转链接走一遍 | 每种可交互元素都有指示器，不只是链接；跳转目标带 `tabindex="-1"`；隐藏待聚焦用 `clip-path`，不用 `left:-9999px` |
| 字体栈真的能取到 | 把声明顺序与 Windows、Android、`zh-CN` 环境下实际存在的字族逐一对照 | 排在必然存在的字族之后的字族是取不到的；等宽栈缺中文家族时，中文标签会静默掉到系统默认 |
| 维护承诺属实 | 把页面或 `DESIGN.md` 里任何关于 CSS 如何工作的说法拿去和 CSS 对照 | "只改一个值，整条字阶跟着变"必须与硬编码 `font-size` 的实际条数吻合，差一条都不算 |
| 生成页就是生成器的产物 | 重跑生成器，把输出和即将交付的文件做 diff | 没有任何差异。手改一个生成出来的页面，等于做一次下次构建会静默删掉的改动；同一条文案改动只出现在一种语言、另一种没有，就是这么来的 |
| 每条路由只加载它跑得起来的东西 | 在读者默认进入的那门语言下，逐条路由查看网络面板 | 没有任何路由取回它执行不了的脚本。只要模块图里某个已经可达的文件静态 `import` 了同一个模块，动态 `import()` 就不构成拆分；页面只需要一个模块的只读部分，那部分就该单独成文件 |
| 预算是四个测出来的数 | 冷缓存、按中端移动网络限速：把落地路由在首次绘制前传输的字节加总，从 Performance 面板读 LCP 与最大的一次布局偏移，并数清这条路由实际收到的每一个脚本，包含加载后由 `import()` 拉取的那些——然后去读 `DESIGN.md` 里记录的值 | 记录值与实测值是同一组四个数，并且落在[视觉方向](visual-direction.md)的上限之内；确要超额，就要指名由哪一个文件承担、读者因此得到什么。页面稳定后仍在移动的元素就是偏移源：在加载时和两秒后各读一次元素位置，而不是相信"换字体应该不会抖" |
| 新增一个项目只动一处 | 在纸面上追一遍：要让一个新案例出现，每个语言目录下必须改哪几个文件 | 只改一个内容文件，其余一律不用碰。新增一个案例要改四个文件的结构，就是这个人一个月后不再更新的结构；而这一条，任何静态检查都不会替你报出来 |
| 原生对象未变形 | 与来源文件逐一比对 | 比例与构图保持；没有为填满容器而放大 |
| 没有顶替缺失作品的图 | 把每张图和它声称展示的材料对照 | 每张图要么指向这个人真实做过的东西，要么有标注出处；没有用生成氛围图替空缺的产物，页面上也没有制作流程标签——不挂"AI 概念封面"徽标，不在可信数字上贴"示例数据" |
| 主张与证据一致 | 把每个数字与它的口径、出处对照读 | 数值、周期、范围都写明；没有任何放大 |
| 没有空格子 | 找"计划中""即将上线""占位"的分区 | 已删除，或填入真实材料 |
| 对方向做替换测试 | 把另一个行业的内容填进第一屏 | 页面在那个行业下会显得不对；如果照样合适，方向仍是通用的 |
| 控制台与网络 | 每条路由都开 devtools | 无报错；没有依赖第三方必须应答的请求 |
| 交付物里只有交付物 | 列出实际交付的目录 | 没有草稿页、没有实验元数据、没有文件在名字或内容里暴露它来自哪一组对照。内部记录应放在读者走不到的地方 |

## 对照着改，不要凭感觉改

一次只改一处，用相同宽度重新渲染，与上一版截图对比。多点盲改会让你无法判断是哪一次改动起了作用，常见结果是页面一边往默认产出漂移，一边看起来更忙。

判断时保持输入不变。用同一份简历重建两次，是唯一能诚实看出"某个决定确实改善了页面"还是"只是内容本身在撑"的办法。两个候选方案并排比较时，用相同宽度、相同滚动位置对照看；先后浏览会高估后看的那个。

两个便宜且值得跑的诊断：

- **首屏测试。** 在 1440 和 390 打开，不滚动，写下陌生人会说这个人是做什么的。如果答案是一个品类（"产品""后端"）而不是一个具体主张，说明首屏没承重。
- **四分钟测试。** 通读整页，标出注意力掉下去的位置。连续多屏重量相同、或者滚动长度已经超过材料本身能提供的东西，是最常见的两个原因。

## 修复顺序

按此顺序解决，因为后面的每一项，返工成本都比前面的低：

1. 方向错误或缺失（替换测试不通过）。
2. 层级与每屏重心。
3. 字体：阶梯、行长、行高、真实渲染字族，以及文字表面——不该带标点的角色上的标点、单位、数字格式。
4. 空间：节奏、分组、分区分隔。
5. 颜色与对比度。
6. 控件几何：圆角这一族值及其理由、嵌套圆角，然后才是各种状态。
7. 媒体处理与裁切。
8. 动效与微反馈。

在第 1 步就不成立的页面上打磨第 8 步，产出的是一个动效精良的通用网站——这正是生成式作品集最常见的失败方式。
