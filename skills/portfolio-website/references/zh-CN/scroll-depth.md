# 深度与奇观

位移、层次和三维是让页面显得贵的最快办法，也是让作品集什么都没说成的最快办法。读者滚完一段动效，却对这个人的作品一无所知，那就是用装饰收取了注意力——而有经验的评审现在一眼就认得出这种痕迹。

材料本身有静态版式讲不出来的东西时才值得做深度：顺序、尺度、厚度、随时间变化的状态。一场持续四小时的故障可以被滚动擦过；一只器物有壁厚；一次迁移有先后；一张照片有景深。一份六条要点的简历没有。

## 先让材料过关，而不是让野心过关

加任何分层动效之前，在 `DESIGN.md` 里回答三个问题：

1. 深度在这里揭示了什么静态构图藏起来的东西？把属性说清楚：顺序、时长、厚度、距离、状态。
2. 这个人的作品里，哪个具体对象具有这个属性？指出它。
3. 低功耗设备、慢网络、以及请求了减少动效的读者，页面降级成什么？降级结果必须仍然是一张完整、可读的页面。

如果对前两个问题的诚实答案是"这样比较好看"，那就做静态页面，把力气花在字体和证据上。

## 每种技法换回什么

按"对一个正在决定要不要雇用某人的人有多少帮助"排序。

| 技法 | 教会读者什么 | 代价 |
| --- | --- | --- |
| 钉住的上下文列 | 论点滚动时，主张、指标或示意图一直留在眼前。这是作品集里回报最高的深度范式 | 成本不大；但钉住的块绝不能盖住它正在解释的东西 |
| 滚动擦过的真实数据 | 一个手势里同时给出时长、顺序和因果：故障时间线、构建的延迟曲线、釉料随窑温冷却的过程 | 必须真有这份数据。为了做擦除而编造数据，比不做更糟 |
| 保留阅读位置的路由转场 | 让人感觉到这是一份连续文档，不是一堆互不相干的页面 | 便宜，而且是用户唯一会稳定感知为"质量"的动效 |
| 真实物件自身的多层视差 | 物件本身的纵深：印刷跨页、装框的画、取芯样品的层理、层层叠起的服务架构 | 只有分层属于物件本身时才成立。单纯前景背景不同速就是壁纸 |
| 把真实对象做成三维 | 体积、榫接、比例：一只器物、一个零件、一体建筑体量、一件买方会要求看各个角度的产品 | 做起来贵、载进来也贵，而且必须赢过一张好照片。赢不过就用照片 |
| Canvas / WebGL 场、生成式纹理 | 当作品本身就是生成式、空间性或数据驱动时，它给出节奏和材质感 | 这是最容易被误认成模板的一种技法，必须由作品来证明它该在场 |

## 组件尺度上的冲击

高级感不只有滚动叙事。一小批组件级特效，承担了人们说"这页看起来很贵"时所指的大部分，而每一种都是一个有特定职责的机制，不是一个可以直接放上去的预设。

| 效果 | 它真正在做什么 | 必须成立的条件 |
| --- | --- | --- |
| 带光源的倾斜 | 让一张卡片读起来像个有正面、有厚度的物件，值得翻看 | 外层点击区固定，只有内层在动；图片边缘保持完整；离开时归位；触屏用户不靠悬停也拿到同样信息 |
| 流体胶囊 / 形变 | 一个带品牌感的主操作，或一次真实的状态变化 | 形变全程文字与点击区稳定；形状不要追着指针跑出手指底下 |
| 共享元素展开 | 从索引进入细节时保持连续，读者知道自己从哪里来 | 一次转换只有一个共享元素；不出现重复导航或残影标题；系统返回键能回来；特效失效时普通链接照样可用 |
| 磁吸牵引、数字滚动 | 轻微的手感反馈；一个确实在往真实数值上数的数字 | 动的是内容而不是目标，位移有上限；最终数字就是实际数字，绝不虚增；关掉动效也落在同一个值上 |
| 阻尼抽屉 / 面板 | 联系、筛选、一件临时任务 | 关闭、Esc、焦点归还、滚动恢复都成立；不重复索取页面已有的信息 |
| 光晕 / 动态边框 | 局部的聚焦与定位，一两处就够 | 运动时对比度仍成立；会收回；低性能设备有静态版本 |
| 弹簧交错 | 一组真的会重排的东西——筛选、分类 | 动画开始前选中态与结果已经正确；连续快速操作落在最后一次选择上，而不是落在最后一个动画上 |
| 按压微缩放 | 确认这次点击生效了 | 120–200ms，点击区不偏移，取消与失焦时复位。它不是触觉反馈，也不该说成是 |
| 自定义光标 | 指针本身即品牌表达的桌面展示片段 | 普通指针照常可用；在浅色、深色、链接、按下状态下都清晰；不放在带 transform 的祖先里 |

其中两三种，因为材料确实在问它们能回答的问题而被选中，那是有判断力的页面。九种全上就是一座组件展馆，而看过展馆的人会当场读出来。每一个都用滚动叙事的三个问题过一遍——它揭示什么、作品里哪个物件真有那个属性、降级方案是什么——诚实答案是"这样会更带感"的那几个，就该出局。

特效画廊和提示词合集公开的是成品配方；为什么照抄会赔掉站点自己的身份，见[参考研究](reference-research.md)。要取的是机制，规格由自己写。

## 哪些一看就是生成的

劫持滚轮、每个板块都 fade-up、与作品无关的 WebGL 粒子场、数字自己往上跳、自动轮播、跟随光标的光晕，以及任何只有按作者本人的滚动速度才走得通的序列。它们的共同点是打断阅读，用来宣布"这里花了功夫"。

## 建造成可以被拿掉的样子

- 只动 `transform` 和 `opacity`。滚动路径上其他属性都会触发重排。
- 滚动计算只用一个 `IntersectionObserver` 加一个 `requestAnimationFrame` 循环。屏外的全部暂停。设备像素比封顶 2。
- 每个媒体元素都写明尺寸，折叠线以下的区块用 `content-visibility`；主视觉在动、页面同时在重排，恰恰砸掉了奇观最想证明的那件事。
- 降级依据不止一条信号：`prefers-reduced-motion`、设备报告的记忆、有效连接类型，以及在真实中档手机上量到的首帧。等级要在绘制之前定，不要在之后补救。
- 整体控制在[视觉方向](visual-direction.md)的预算之内。在一张别人用来对你做判断的屏幕上，压垮关键路径的奇观是一笔坏买卖。

减少动效那条路径是拆除，不是遮掩。动效关掉后内容必须到达它的最终状态；静态排版本身要能通过[视觉验收](visual-review.md)里的每一条检查；关掉 JavaScript，页面仍应靠文字把主张讲完。还有一个细节：系统已经请求减少动效时就把开关置为不可用，等于恰恰从最想把它要回来的人手里夺走选择权。

永远不要把证据锁在效果后面。读者需要核验的东西，不能只存在于某个动画帧、只在悬停时出现、或者必须经过被劫持的滚轮手势才能到达。

## 只留一件招牌

页面上应该有一样东西真的出色：钉住的案例叙事、一条被擦过的时间线、或者一件三维渲染的对象。每个板块都做到七成野心的站点，读起来像一个预算没花完的模板——而这种质感，评审一眼就能叫出名字。

## 确认时间线看的是整页

滚动驱动动画可以写得完全正确、确实存在于 DOM 里，却一动不动。`overflow: hidden` 会让元素变成滚动容器，而 `view()` 时间线是以最近的可滚动祖先为参照的——所以一张靠 `overflow: hidden` 裁圆角的卡片里的视差层，进度是相对这张卡片算的，永远停在起始偏移上，看上去就成了两层之间一道始终对不齐的缝。要裁切就用 `overflow: clip`，它不产生滚动视口；或者把具名的 `view-timeline` 挂在一个确定是整页的祖先上。

这个故障在截图里看不出来，控制台里也看不出来——时间线解析失败不会报任何错。所以要量：在四个滚动位置读 `getComputedStyle(el).transform`，至少要有三个不同的值。同一个探针还能抓住另一种静默故障：`steps()` 擦除动画的轨道比它滑过的舞台还窄，于是一次露出三帧、上一帧在裁切边被切成半张——让轨道宽度正好等于每一帧的宽度。

机构跑对了不等于画面立住了。一帧帧确实擦得准确的招牌，仍然可能读起来像没做完。四条几何检查，都在浏览器里量，不要盯着代码判断：

- 钉住的那个盒子高度等于内容高度。写死的 `height` 大于里面的卡片，卡片就被钉在视口顶部，整段擦除过程下方都空着一截——258px 的卡片放进 440px 的舞台，每一帧都有三分之一是空的，动画再正确也补不回来。滚动距离由外层包裹容器提供，舞台只需要装下一帧。
- 网格项一旦同时带上 `max-width` 和 `margin-inline: auto` 就不再 stretch，会收缩到文字宽度，于是舞台满宽、卡片缩成一条。给帧本身 `width: 100%`，子元素显式排位。
- 变换可以推翻静态排版早就修好的避让，所以会动的覆盖层必须在它**去到的位置**测，而不是在它落位的位置。有一张成品页把标注板放进卡片里、补了 `padding-bottom`，它就不再盖住来源行了；接着视差关键帧在每个滚动周期的一段里把它抬回 54px，正好压回来源行上。静态截图和只看布局的检查都看不见这件事。由此得出四条规矩：
  - 给浮动的板子一个**单向**位移，或者把位移限制在你真正量出来的净空里。对称的 `±54px` 动画会到达布局位置*上方* 54px，而布局只被验证过从这个位置往下。
  - 遮挡要按**绘制顺序**判断，不能只比矩形相交。在多个宽度上扫过整个滚动区间，对每一段文字用 `document.elementsFromPoint` 问：在它自己那行的行盒内取一个点，谁画在上面。板子的矩形和标题的矩形相交不代表盖住了任何东西，因为 z-index 更高的不透明吸顶头部本来就画在它上面。有两种偷懒会白跑一次验证：采*元素*而不是采文字，覆盖层的所有祖先都会进结果——卡片自己的链接包含那块板，于是它的 `textContent` 也带着板的文字，检查就把你的标注报成被遮挡；只比矩形不问谁先画，会把一次普通的吸顶路过报成缺陷。
  - 把路过和停在原地分开。读者滚动时文字从吸顶条*底下*滑过，那是这条的本分；这样报，市面上每个网站每行文字都会出一条结论。真正要量的是页面停下来那一刻：每个页内锚点都按浏览器落裸片段的方式落一次，再问读者点中的那个标题是不是压在条底下。净空写在滚动容器上——`html { scroll-padding-top: calc(var(--header-h) + 14px) }`——一处写好，所有锚点同时合格；既不写它、也不在目标上写 `scroll-margin-top`，每次点链接都会让章节标题的顶部被头部吃掉一截，读者体验到的是"这个链接没带我到哪里"。别去缩头部。写这个检查有一个坑：`scrollIntoView({ block: 'start' })` 认 `scroll-margin`，却不认根滚动容器在片段导航里用的 `scroll-padding`，所以它会在设对了属性的页面上报缺陷，在两个都没设的页面上放行。落点要自己算——目标偏移减去 `max(滚动容器的 scroll-padding-top, 目标的 scroll-margin-top)`。
  - 每一个滚动位置都重新量一次几何。滚动之前抓下的矩形描述的是另一页：瞄准一句话原来所在的像素，那里已经被别的东西占住，于是占在那儿的最上层元素被冤枉成遮挡者。在一张成品页上量到：812 段文字里 78 段报被盖住，全部是吸顶头部，原因只是坐标过期。
- 用很小的 `viewBox` 画好再放大的图表会同时说两个谎。线宽跟着一起放大，2.4 单位的线落地成 12px 的粗条，所以要设 `vector-effect: non-scaling-stroke`；而按当前可见片段归一化的曲线会被压成顶部一条平带——改成对整份数据归一化，并把整条序列画在高亮段背后，画面填满了，读者也看清了这一周落在整月的哪个位置。

## 打分时别被自己骗

评审会被动效吸引，所以页面必须能承受动效缺席。

1. 在固定滚动位置取五张静帧，再关掉 JavaScript 看一遍。逐张记下读者学到了什么。学到的是类别而不是主张，说明这段序列是装饰。
2. 把静帧模糊或去色。层级必须在没有动效时依然成立。
3. 在动效运行中的状态下于 360px 截图。手工搭出来的深度物件，是整页最可能在手机上出问题的一样东西。
4. 在真机上测量，不要用模拟器，记录帧时间和传输字节。
5. 对动效本身跑换人测试：如果同一个技法、同样的时长和缓动放在另一个领域的人身上也毫无违和，那它就是为效果而选，不是为材料而选。
