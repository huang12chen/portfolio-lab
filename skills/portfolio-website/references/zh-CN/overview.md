# 定制个人作品集

[English overview](../../SKILL.md)

默认按真人材料组织作品集。用户已明确授权虚构教学示例时，按需阅读[虚构演示与公开交付](demo-projects.md)，清楚标注虚构身份与模拟内容，不能把它们写入真人简历。已有授权持续有效，不另设普通设计审批关卡。

作品集帮助特定读者判断“这个人能做什么、具体做过什么、负责哪一部分、依据是什么”。以真实材料形成案例与阅读路线，再设计视觉。成品可共享、可维护，体现人的特点。

## 理解这个人和目标读者

读取已提供的简历、作品、链接、截图、视频和反馈。先提炼目标（求职、接单、研究交流或展示）、主要读者、核心能力、已有材料、公开范围和个人风格。

缺口只问会改变判断的问题，例如目标方向不明、个人贡献不清或关键材料没有依据。复用已确认的信息，允许姓名/联系方式留空；不要让用户重复填写简历或完成长问卷。继续完成不依赖回答的设计与整理。

按需读 [材料与证据](content.md)。原始材料、改写内容和设计假设分开保留。不要把简历逐段搬进网页就称作完整作品集，也不捏造客户、成果、作品和指标。

## 根据内容决定结构和风格

读 [行业、数量与案例适配](structure.md)。先整理项目与能力的映射，决定精选、完整目录和案例深度；数量不是固定的三个，风格不是固定的画廊绿。

- 少量作品深讲过程与判断；大量作品有策展与索引；没有正式作品时明确自主练习/概念项目及真实可展示的过程。
- 第一屏说清定位和价值。项目概览让读者知道有什么、各项目可以看到什么、先看哪个或怎样选择。
- 用项目的具体名称做主标题，文艺表达可以作为辅助。区分工作职责、个人贡献、团队素材与最终结果。
- 代表性图片、原始截图、片段、代码或方法应直接可见。补充资料可另开，核心内容不藏在多次点击后。

克制不等于方向。读 [视觉方向](visual-direction.md)，从读者任务、材料里的原生对象、该行业的证据形态、维护约束这四个输入推导形态，写下三句话的方向声明，再做替换测试：换成别人的行业仍然成立，就还没定下来。字体、颜色、间距、动效、图像都由这句声明往下推，而不是在区间里挑：[视觉方向](visual-direction.md) 说明了为什么区间只能约束、不能生成，并列出应当先从真实文件里量出来的属性——宽高比、从材料某个具名位置采到的色相、结构有几级、密还是疏、顺序型还是空间型。一份密集陈述的页面和一个论证型页面需要不同阶梯，一个人的配色不能变成所有人的。

方向定下后读 [表面、光与层次](surfaces.md)：记录光在哪里、有多硬，表面层数从材料自己的物件有几处相接来取，再为每条边界选定分隔手段——色阶、投影、细线或模糊。陶艺师叠放的样片、工程师同一平面上的示意图、修复师的纸板—皮革—书脊，是三种不同答案；一个页面若对三者给出同一个答案，就还不是推导出来的。

接着读 [空间构造](spatial-construction.md)：写出页面有几层深度、每层允许放什么；重叠的数量从材料的物件是否被自我标注、是否物理叠放、是否是前后对照来取；给网格定一个破格额度；并让页面上有一个纵向间距明显大于其余所有间距。一套好配色下的通栏块堆叠，仍然是堆叠。

选择适合目标读者和素材的视觉方向，写入项目的 `DESIGN.md`。当某条参考真的影响了设计，读 [参考研究](reference-research.md)：顺链路走到具体站点或组件那一层，记下实际到达的深度，写出观察—改造—验证三段。本技能自带所需的全部说明，参考文件按需读取。

## 建立读者能走通的主线

默认路径：定位与概览 → 一次点击到完整案例 → 贡献、材料和方法 → 明确返回/相关项目。可按内容采用单页、案例页、专题集或混合结构，不强制页面数量。

每个案例围绕证据安排顺序：背景/任务、本人职责、代表材料、做法与判断、结果及边界。它们可以合并或调整，避免硬填固定标题和空段落。

- 打开后立刻知道是哪项工作、有什么可看；核心材料默认展开。
- 完整案例不再套一个必须先点的预览弹层；图片放大可选，不作为理解项目的必经步骤。
- 导航名称与去向一致，约定好“作品”“返回列表”“首页”。从其他页面回来、浏览器 Back 和锚点跳转都要实际检查。
- 联系方式按用户选择显示。联系弹层需要清楚关闭与恢复；未提供的资料不要用假邮箱、假姓名填上。

## 将材料做成可信的呈现

读 [媒体与导航验收](images-and-links.md)，并在修改已有作品集前查看 [作品集改进指南](review.md)。阶梯定下来之后读 [字的落地执行](typography-execution.md)：按数字被阅读的位置决定数字模式、位数必须有依据、`balance` 只用于标题、栏边要光学齐平——一个页面可以通过所有阶梯规则，仍然看起来没被排过。要加视差、滚动联动或三维之前先读 [深度与奇观](scroll-depth.md)：门槛是材料里是否有静态版式讲不出的顺序、尺度、厚度或状态。

作品图、视频、截图、文档、数据图和代码分别选择适合的阅读方式。图片按照原比例与主体组织，完整可见、对齐有意图；长文有适当行长；指标紧邻口径和证据。数值摘要不能代替材料本身。

未知数量的后续素材不提前制造空格子；有多少真实内容就合理组织多少，保留易扩展的数据结构。素材不足时先完成现有版本，并明确缺口对案例说服力的影响。

按任务选择动效和组件，保持稳定点击区、清楚反馈与触屏替代。在排布任何重复组件之前读 [组件解剖](component-anatomy.md)，招牌动作之外凡是会动的东西都先读 [动效编排](motion-choreography.md)：时长按位移推出、缓动是对物理的陈述、只有次序本身就是论证时才错峰、减少动效那条分支要保住信息而不是删掉内容；交付之前读 [交互状态](interaction-states.md)：页面上没有任何条件能进入的状态，等于没设计过；缺部件的组件在任何圆角值下都读起来像半成品。不要为展示交互而让读者迷路或增加阅读步骤。在写下任何媒体查询之前读 [响应式的构造](responsive-construction.md)：按读者的需要给内容排序、指明必须在重排后存活的关系、逐表判断论证是在列间还是行间，并且永远不要用隐藏溢出代替修好造成溢出的那个物件。

## 实现、验证、交付

实现可运行的网站，接入已有材料并检查实际路径。在把任何一页称作完成之前读 [一眼是生成的](reads-as-generated.md)：每个可见元素都要能追溯到材料里的一个事实或读者的一项任务，而成品要与上一份同源产出做比较——强调色色相距离、颜色角色命名、首屏骨架、不同取值个数——因为"两个人的站点像一个人做的"是任何单看一页的评审都看不见的失败。按 [视觉验收](visual-review.md) 检查渲染结果：每屏重心、去色后的层级、真正渲染的字体、实测对比度、组件状态，以及修复顺序；一次只改一处并在相同宽度下对比截图。用真实浏览器查看桌面、用户反馈的尺寸和平板/窄屏；测试每类媒体、每条主导航、筛选、返回、关闭、键盘和减少动效。

这些检查大多已有可执行的形式。在本技能目录下运行 `node scripts/selfcheck.mjs <构建产物目录>`：先跑结构规则，再用真实浏览器在三个宽度上测布局、对比度、遮挡与质感探针，逐层给出判定。三种判定状态、检查码与参考行的对照表、以及没有仪器可测、仍属判断题的三十一条检查行，见 [自检](self-check.md)。跑干净只能作为它所覆盖那些规则的证据，别的什么也不能说明；NOT-MEASURED 是测量器的边界，要如实报出来，不能四舍五入成通过。

在宣布完成前，在渲染后的页面上实测以下六个值，并记录测得的结果。这些项在源码里都像已经完成，却会在浏览器里静默失效：
- 最小渲染字形在乘上 SVG 屏幕 CTM 之后仍不小于 11px——缩放坐标里的图表文字不是它在属性上写的那个字号；
- 每个页内锚点在每个断点都停在吸顶栏之下，目标标题不被遮住——读落点，不看跳转过程；
- `:focus-visible` 覆盖每一种可交互类型，包括链接——逐个按 Tab，只写给 `button` 的规则不会给锚点描边；
- 实际绘制的字族与字重等于声明的字体栈（`CSS.getPlatformFontsForNode`），页面提供的每种语言都要测——回退把一行标题拆成两种字体，读者会把它读成缺陷；
- 标题、标签、导航项、按钮、徽章不以句末标点结尾；
- 每个 `font-size` 都来自 token，且它引用的每个 `var()` 都在该路由加载的样式表里声明过。

无浏览器时明确验证限制，不要把没测过的项写成通过。

最后用读者任务验收：能否快速说出定位、找到相关作品、看清本人贡献与依据，并顺利返回或联系。修复主体裁切、入口失效、材料缺失、虚假暗示等问题，再交付。

按用户和当前平台授权提供源码、预览/托管结果与内容维护方式；保留现有受众和公开范围。发布状态与本地测试分别说明。共享技能与模板不包含用户简历、私有图片、账户身份、凭据或个人偏好配置。
