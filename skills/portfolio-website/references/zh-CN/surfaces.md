# 表面、光与层次

页面显得昂贵还是廉价，主要看边缘：一块表面在哪里结束，下一块在哪里开始，这条边界是被描出来的、被照出来的，还是直接用了框架默认值。"阴影"是作品集工作里最没被定义清楚的词——[视觉方向](../visual-direction.md)禁止每张卡片挂同一个阴影，却从没说第二个阴影应当由什么构成。本文件不给任何定值。下面每一条机制都从材料推导，然后在渲染出来的页面上量。

先在 `DESIGN.md` 的方向声明里补一行：光在哪里、有多硬、材料里真正叠了几层表面。没有记录光源的页面通不过本文件任何一条检查，因为没有可以对照像素的基准。

## 从物件被观看的方式推出光源

| 材料里的条件 | 关于光的结论 | 页面随之怎么做 |
| --- | --- | --- |
| 物件在单一灯位下被拍摄或陈列——器皿、标本、玻璃框下的版画 | 一个方向、一种硬度、所有物件的投影同向 | 全站一套阴影配方，每个抬起元素的偏移方向一致 |
| 在环境光下阅读的扁平印刷物——账页、总谱页、数据表 | 没有主方向；分隔靠的是纸上落墨 | 不用投影；边界全部由色阶、线与折痕承担 |
| 拿在手里转动的物件，或本身带景深的场景——野外器材、装框叶片、窑内码放 | 光与距离一起变 | 模糊与阴影都随深度变化，而这个变化就是页面要动的东西 |
| 屏幕、仪表盘、同一平面上的示意图 | 没有光，只有层序 | 层次用叠放顺序与包含关系表达，绝不模拟材质 |

推导的是硬度而不是数值：物件离它投影所在的表面有多远，半影相对物件本身有多宽。两者都能从材料自己的照片里量出来，这也正好是诚实的出处。

**检查。** 在最顶层的抬起元素上读取计算 `box-shadow`。如果只有一层，或者每一类抬起元素都带着完全相同的偏移与模糊之比，而方向声明里没写光源，就不通过。材料明明是一叠实物，页面上却只有一个默认阴影，这正是本文件存在的理由。

## 表面系统需要几层

去数物件本身有多少个分隔面，而不是凭审美定。陶艺师的工作台面是窑板、素坯、釉试片、贴在圈足上的一张纸标——四样互相接触的东西，有意思的是谁压在谁上面。古籍修复对象的层次是木板、皮革、书脊、环衬以及下面的衬页粘贴处，四个色阶就能把一次修补的层序讲清楚。后端工程师的材料是一张画在同一个平面上的依赖图，这类站点上任何物理堆叠都是从产品仪表盘借来的。

从这个清单取层数，再减去读者不需要看见的分隔。一层，说明页面就是一张纸，只给线；两层，图与底，可以有一套阴影配方；三层是工作上限：画布、面板、抬起。只有当材料自身确实有四层互相接触的东西，四层才成立，也才值那个成本。如果问的是"几层好看"，每次构建都会落在两层。

**检查。** 统计实际交付的 CSS 中不同的层次类数量——真正被表面用到的 `background` 与 `box-shadow` 组合——与 `DESIGN.md` 记录的层数对照。多于材料支撑得起的数量就是装饰，少于读者必须分辨的边界数量就是平的页面。任一侧差出超过一层即不通过。

## 相邻两层之间用什么分隔

按材料自己在这条边界上已有的做法来选。四根杠杆，而且同类边界全站必须用同一根。

| 手段 | 什么时候对 | 什么时候错 | 怎么验 |
| --- | --- | --- | --- |
| 色阶推移 | 两层是同一种东西——纸压纸、化妆土压坯体 | 调色板级数太少推不出可见差，或者这个推移其实在替颜色干活 | 计算相邻两面之间的明度差；低于灰度下仍然分得开的门槛，说明这条边界对色盲读者与灰度截图根本不存在 |
| 投影 | 一个物件物理地压在另一个上面 | 物件是画出来的不是放上去的——线框、示意图、代码块 | 见下面的层结构，加上方向审计 |
| 细线 | 边界是被描或刻出来的：盘口、栏线、五线谱、刻版标签 | 每张卡片都套同一个 1px 描边，那是组件库不是边缘 | 数只有 border 而没有其他分隔手段的元素；全靠线撑住分隔的页面是线框图 |
| 模糊 | 有半透明东西压在可读内容之上：硫酸纸、湿裱、玻璃 | 材料是不透明的，磨砂面板就是壁纸 | 每个 `backdrop-filter` 都要在 `DESIGN.md` 里写出它对应哪种半透明材料，写不出来就不通过 |

**检查。** 在不同路由上各挑三条同类边界（卡片压画布、面板边、浮层接缝），读出各自用了哪根杠杆。同类却不同手段，说明表面系统从未被决定过，只是一屏一屏地猜。

## 阴影的结构，不是阴影的数值

阴影是一个列表，列表的长度才是决定。按三个角色搭：

1. 接触层：紧、半径小，偏移略大于物件自身厚度。它负责让物件像是放着的，而不是飘着的。
2. 半影层：模糊大得多、强度低、偏移方向与接触层一致，两者之比由光的硬度决定。硬光让两个偏移接近，漫射光允许半影漂开。
3. 空气层：只用在最高一类元素上，让浮层与它可能盖住的一切分开。

色相：中性黑投影压在带色温的画布上会读成灰污。把每一层的色相朝它所落的那层表面的色相推，比那个底色更暗、饱和略高，因为真实地面的反射光会回到阴影里。同一个阴影色用在两种画布上，至少在其中一个上是在谎报地面。

硬度藏在一个比值里而不是像素数里：偏移除以模糊。每个光源记下这个比值，让所有阴影从它推导自己的偏移，这样找到对的光时整页一起动。

**检查。** 读三个最高抬起层级的计算 `box-shadow` 列表。通过要求：凡被描述为"压在页面上"的元素都有多层；层与层之间偏移与模糊之比单调变大；每一层的方向都落在记录的光源同一象限。然后取某元素下边缘外侧一行像素与上边缘外侧像素采样：如果阴影色相与画布色相完全相同，那是灰色，不是这块画布上的影子。

## 为什么同一份配方到暗底上会失效

暗投影压在暗表面上不携带任何信息：已经没有可压暗的余量，于是层次消失，而 CSS 还写着它有。暗底上的分隔靠的是光进得来，而不是光到不了，三种替代手段是：提亮顶边（朝光那一侧的内高光）、一层让整面微微抬起的极淡内发光、以及一条比表面亮一档而不是比地面暗一档的细线。

按前面同一份材料清单来选：烧过或上釉的边缘会有亮唇；哑光或植绒面只是抬起；刻出来的边界给那条亮细线。外部投影也要留着，只是减弱，因为暗底上抬起的物件仍然从下方拿走光——只是不能只靠这件事。

**检查。** 截图：抬起元素停在页面上最暗的那块表面上、状态已稳定。把它顶边那一行像素的平均亮度与面内部亮度对比，提亮的边必须有可见台阶。若差值落在测量噪声内，而所有 `box-shadow` 层都比表面本身更暗，那这个元素没有层次，页面只是自以为有。

## 真实屏幕上的细线

1 个 CSS 像素不等于 1 个设备像素。在两倍、三倍密度的屏幕上，`border: 1px` 会被画成柔化的两到三个设备像素，在小控件上读起来就是一团脏；在低密度屏幕上，同样的声明换成小数宽度会直接归零，边界消失。两种处理，而且每条线都要说是哪一种：

- **设备细线**，用于必须读作一个设备像素的边——数据视图内的分隔线、表格线、盘内线。声明为半个 CSS 像素，或用按密度缩放的伪元素绘制，并在 `min-resolution` 查询里重新声明，让它在密度变化时始终是一个设备像素。
- **墨线**，用于材料自己画出来而非被照出来的边界——印刷页、手稿、刻版。整整一个 CSS 像素，强度按它所在的地面设定。

全局出错的地方是强度。一个低透明度的 `--border` token 在暗底上不可见、在亮底上是一道抹痕，因为眼睛读边界读的是对比台阶，不是 alpha 值。强度要从所在地面推出来，按地面存，不按组件存。

**检查。** 把每个元素的计算 `border-width` 乘上 `devicePixelRatio` 并报告两个值。声称是设备细线而乘积不等于 1 的，就是 2。再找出同时用在亮底与暗底上的那条边界色 token，在截图里分别量边界两侧的对比台阶；只要有一侧低于读者仍能看出边界的水平，就说明一个共享 token 在干两件它干不了的事。

## 颗粒、噪点与抖动

颗粒是让平页面变成材质最便宜的办法，也是让页面显脏最便宜的办法。对任何行业都成立的规则：

- 用亮度噪点——三个通道同一偏移。彩色噪点是压缩产物，任何材料都没有它。
- 颗粒属于表面，不属于文档。它给画布和同材质的面板，不给本该抬起的卡片——那会吃掉阴影。
- 一律避开读者要解码的东西：文字、数据、代码、图表标记。文字压在纹理上，纹理就进了对比度计算。
- 量：上限由结构定，不由"好不好看"定。同一色相素面区域内部的纹理波动，必须明显小于相邻两个层次之间的明度差，否则颗粒比它本该待在内的版式更响。
- 大面积色阶坡道要同时给抖动和颗粒；纹理页面上出现一道平滑渐变，正是两者必须相遇的位置。

**检查。** 在渲染页面上取两块名义同色的区域：一块带纹理的素面，一块关掉纹理的对照区，各报每通道标准差。不通过的情况：纹理存在但波动接近 0（管线抹平，等于没上）、纹理波动接近或超过相邻层次之间的明度差（脏）、色度波动非零而三通道亮度波动不相等（彩色噪点）、文字块包围盒内出现纹理。坡道另测一次：取坡道区域内相邻行之间的最大明度台阶，台阶大于颗粒自身的标准差，说明渐变在分层，而颗粒没盖住它。

## 内高光与内边成对

外部阴影与内部边缘是同一个决定，而页面常常只做一半。抬起的物件在朝光一侧有内高光，在背光一侧有柔和内暗。下沉的物件两者都反过来：内侧顶部暗影、内侧底部亮线。两层内边都是一个台阶，不是渐变，并且跟随上面记录的光源。

两种要盯着的错误：一个元素同时带外部投影与内侧顶部暗，读起来像一个带盖的洞；抬起元素完全没有内边，读起来像一个平形状下面抹了一道，这正是生成输出的默认产出。

**检查。** 对每类表面读取计算 `box-shadow`，按 inset 与非 inset 分组。通过要求：被描述为抬起的元素有非 inset 层，并在朝光一侧有比面更亮的 inset 层；被描述为下沉的元素有 inset 层且没有投影；没有任何元素同时带强投影与强内暗。报告每一类中 inset 暗层多于一层、或所需内边完全缺失的情况。

## 代价

每一点纹理、滤镜与模糊都是绘制成本，其中一些还在滚动路径上按像素计费。表面类的数量要少到能在 `DESIGN.md` 里逐一点名，低功率档位上关掉噪点与模糊，并且保证去掉全部表面处理（灰度、无滤镜）之后页面仍能通过 [视觉验收](visual-review.md) 的检查。如果拿掉纹理之后层级也没了，那是纹理在替结构干活，而结构需要一个真正的分隔手段。这些表面的按下与悬停处理见[交互状态](interaction-states.md)；一块表面允许装哪些部件见[组件解剖](component-anatomy.md)。
