# 空间构造

[表面、光与层次](surfaces.md)决定页面由什么构成，[交互状态](interaction-states.md)决定页面如何回应。两者都没有规定页面静止不动时东西在深度上的位置，而缺口正在这里：标记语言组出来的是一个个通栏块叠成的柱子，而一套配色良好的柱子仍然是柱子。构图发生在这些地方——一个物件有意挡在另一个前面，某个块拒绝了一次网格，以及某个物件周围的空白明显比别处的空白更贵。本文件不给任何定值。每条机制都从材料推出，然后在渲染出来的页面上量。

先在 `DESIGN.md` 里记录光源的那一行旁边，补上它的空间对应物：页面有几层深度、每一层放什么、以及允许破格几次。没有记录层级清单的页面通不过本文件任何一条检查，因为元素的 `z-index` 没有可比对的基准。

## 层级从哪里来

页面上的深度不是装饰，它是一句声明：某样东西是*透过*另一样被读，还是压在另一样*上面*。材料要么给出这句话，要么不给。

| 材料里的条件 | 它真实的几何是什么 | 页面的层级随之是什么 |
| --- | --- | --- |
| 在物件本身之上做标注——带深度标尺的岩芯、带套准记号的版画、描在自己残片平面上的器皿 | 同一件东西的两套定位，且刻意不完全重合 | 底、物、物上的注记。两套定位之间的偏差就是内容，所以必须在每个宽度上都保住 |
| 物理上可分层剥离的叠放——板、皮革、环衬；窑架、素坯、釉试片 | 每一层都是可以拿起来的真实表面 | 一层真实结构对应一层，别的东西一律不许用这层 |
| 前后对照或修订稿与原稿——涂黑、修复前后、叠在 p50 上的 p99 | 一样东西挡住另一样，重点正是被挡住的那部分 | 用滑块或按键叠合，不要两张卡并排。并排会把整段论证丢掉 |
| 示意图、仪表盘、同一平面上的代码 | 物件里没有深度，只有绘制顺序 | 最多两层：底面，以及唯一浮起来的那件（菜单、提示）。在这里模拟材质是从别的产品界面抄来的 |
| 没有部件也没有状态的单件——一首诗、一张照片、一个数字 | 没有可供表现的层叠 | 零重叠。页面靠尺幅与静默构图，多加一块浮动面板是对物件撒谎 |

**检查。** 读出所有计算 `z-index` 不为 `auto`、且确实画在另一个元素盒子之上的元素，归组。合格要求每一个都能落进 `DESIGN.md` 里已命名的某一层，且实际用到的层数与上表该行材料所暗示的层数相差不超过一层。层数比物件的层数多是为一叠而叠。

## 是层级，不是 z-index 爬梯

`z-index: 999` 是一份写成 CSS 的 bug 报告：作者在某次层序争吵里输了，于是一路加价直到没人压得过它。一旦有元素站在 999，下一个浮层就需要 1000，页面最后变成一串无法从数字判断谁该在上面的编号。做法是把层级声明成一组固定名字——底、结构、物、注记、浮层——并让这五个名字成为任何元素唯一可用的值。真有东西需要压过浮层，它就不是浮层，是 bug。

之所以要用名字而不是数值刻度来修这个问题，是因为名字可以被材料检验，数值不行。`注记` 在 `物` 之上是关于物件的陈述；`40` 在 `30` 之上只是算术。

**检查。** 收集已发布 CSS 中所有不同的非 `auto` `z-index` 值。合格要求它们的个数不超过已声明的层级数加上少量刻意使用的负值，且没有任何值高于 100。然后找出共用同一个值的两个互不相关的组件——那不是层级，那是在等一个浏览器来撞车。

## 重叠必须是论证

作品集页面上的第一次重叠通常被读成失误：标题压在一张读不动的照片上，卡片的一角没来由地掖进另一张下面。要修的不是减少重叠，而是让每一个重叠都成立到读者能说清他在透过哪个看哪个、以及为什么。这句话就是检验。你接不下这句，重叠就是装饰，而这个页面会被一个说不出原因的人评价成"乱"。

让数量少而每一个都承重，数量取自上面那张清单而不是取自品味。然后处理所有人都忘掉的另一半：一个在 1440 活得好好的重叠，通常死在 390，因为两个盒子已经没有地方待在同一个位置。每个重叠都要明确决定它在手机上塌成单层、按比例保住可读的偏差、还是干脆去掉——并写下你选了哪个。一个悄悄变成遮挡的手机端重叠，和 [组件解剖](component-anatomy.md) 数据那节抱怨的是同一个缺陷，只是从另一个方向撞上。

**检查。** 在 1440、768、390 三个宽度下，列出每一对在两个轴向上都重叠超过几个像素的可见元素，逐对报告谁画在上面、下面那件的文字有没有被盖住、以及这一是否在三个宽度上都出现。1440 重叠、390 遮挡的是 fail。没人说得出理由的是 fail。上表该行明明暗示套准或叠放、页面却是零重叠，也是 fail——说明深度从来没有被推导出来。

## 网格只在被打破的地方才看得见

全部对齐的页面并不自动等于构图，它是一张表。版式里的强调和句子里的强调机制相同：是相对的、是稀少的、并且需要一片不强调的底色才量得出来。所以先定下网格、守住它，然后打破它明确规定的次数，每一次都挂在一个读者应该注意到的事物上。什么都没打破网格的页面没有强调的手段可用；每个区块自定宽度的页面没有网格可打破，读者随即放弃定向。

破格额度取自材料自身的层级。三层结构（收藏、册、页）大致换来每层一次破格——用通栏的那件表现收藏，用错位的那件表现一开。扁平的日志一次都不该有，并且应当诚实地扁平着。

**检查。** 在 1440 读出所有顶层内容块的包围盒，对它们的左边缘聚类。合格要求存在一个主簇——那就是网格——以及一小撮、数量明确、落在主簇之外的少数派，并且每一个都对应 `DESIGN.md` 里写明值得强调的那件。零个例外意味着页面无法指向任何东西。多数都是例外，意味着这些"簇"只是各容器内边距的巧合，而这正是"破格感"实际上是一套没说出来的格子的最常见方式。

## 不均匀的空白是空白唯一的承重方式

间距尺度是维护工具，不是构图工具。当页面上每一个间隙都取自同一把尺、且没有一个间隙是例外，那么所有物件一样贵，也就是没有一个物件贵。物件周围的空气告诉读者在还没读一个字之前该在意多少：修复师页面在一开书叶周围放大量空白，因为工作台上的书就是这个样子；仪表盘页面很密，因为密度就是产品。先从材料推出页面整体该多密，然后花掉一个比其余都大得多的间隙，给你最希望被先读的那件。

一个诚实的例外：整页论证就是一个数字或一张图的页面可以几乎全是空白。那是一件物品的构图，只要那件东西确实是原因，它同样通过下面的检查。

**检查。** 在 1440 与 390、静止状态、无运动进行中，量相邻顶层块之间的垂直间距。报告不同值的个数、中位数，以及最大值与中位数的比。比值接近 1 说明每个间距都出自同一把尺、页面没有空间上的强调——这是结论，不是通过。比值很大时，报告最大那个间隙正下方紧挨着什么：页面上最贵的空间应当在一个最重要的物件上方，这条检查专门用来抓那种"页脚之前空出整整一屏"的页面。

## 盒子不是墨

居中是对矩形的陈述，而阅读发生在笔画上。圆圈里的三角形几何居中、视觉偏左下。一栏文字的末行几何对齐、视觉偏短，因为字身余白与斜体的悬挑留下无人过问的一条缝。全角标点自带后随空间，所以以 `。」` 收尾的那一行比旁边的拉丁行离页边更远。悬挂标点、几处修正过的光学居中，就是"排出来的页面"与"摆出来的页面"之间的差别。

从材料推出哪些才要紧：物件是一张印刷页照片的页面在意页边；全是示意图的页面在意图标套圆心的对齐；双语页面在意两侧标点的悬挑。

**检查。** 对每个"在更宽的盒子里居中、且只包含一个字形、一个图标或一个短标签"的元素，比较它盒子的中心与它墨迹的中心——元素的 `getBoundingClientRect` 对上其文字或路径的渲染包围盒。相差超过两三像素就记下来，这个量在控件上一眼可见。然后对每一条右对齐或两端对齐的文本边，逐行核对末字符与容器边的关系；一栏里标点在一行挂出来、在下一行不挂，就是没有经过排版。

## 顺序

先定层级与重叠，再做表面：阴影清单本身在声明一件东西坐在哪一层，而没有层级的元素连落影的表面都没有。先定网格与破格额度，再做动效：滚动驱动的移动是空间主张，需要一个可偏离的空间基准——见[深度与奇观](scroll-depth.md)。组件解剖排在最前：部件之间基线不一致的卡片，无论构图多好都看起来是坏的。这些通过之后，它们的判据应当作为行进入[视觉验收](visual-review.md)，而不是作为建议留在本文件里。
