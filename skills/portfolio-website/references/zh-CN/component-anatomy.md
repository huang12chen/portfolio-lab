# 组件解剖

上一次盲审里的三条结论不是审美失败。没有人主动选择参差不齐的卡片基线、178px 高的目录导航，或者被裁掉论点列的表格——只是组件缺了部件，于是页面以半成品的状态交付。审美难教，部件是一张清单。本文件就是那张清单，外加几条决定"当组件成组出现时部件的边在哪里"的规则。

下面每一条都是浏览器里能测的东西。解剖缺陷不会报错，但每个审查者看一眼都能读出"没做完"。

## 缺陷这一类

一个已构建作品站上量出来的四条发现，在这里作为类别呈现，不是一种可以照搬的外观。

| 量到了什么 | 读者的体验 | 缺的部件 |
| --- | --- | --- |
| 同一行索引卡在 1440 的结束高度分别是 454、479、514，三条操作链接落在三条不同基线上 | 一排本该属于同一套系统的兄弟元素 | 卡内部固定区与伸缩区的划分，以及"读者要纵向扫的那部分必须共线" |
| 案例目录导航在 390 塌成三行参差，总高 178px | 第一屏全是导航，案例还没开始 | 导航项的溢出行为，以及以视口为基准的高度预算 |
| 某个页面自己的 `h1` 用的是正文字号（17.5px），而它的各节 `h2` 是 40px | 页面身份读起来像一段正文，层级被错误的元素承担着 | 把展示级角色绑在真正命名这一页的元素上，而不是绑在最长的那个标题上 |
| 一张 480px 宽的表坐在 291px 的滚动区里，没有任何提示 | 案例赖以论证的那两列不在读者看到的这一屏上 | 一个提示，或者一次回流——两者必须选一个，而且由数据的形状来选 |

**检查。** 每一条都有同一个浏览器探针：兄弟操作链接 `top` 偏移的最大差值；导航自身高度在 390 下占视口的比例；该路由 `h1` 的计算 `font-size` 与同页最大 `h2` 的对比；每张表的 `scrollWidth` 对容器可视宽度，以及提示是否存在。把这四个数字连同取值写进 `DESIGN.md` 的通过／不通过记录。

## 一个组件必须有哪些部件

右列这些部件正是生成产出会漏掉的，而每一个都决定组件读起来是"被设计过"还是"被拼装过"。

| 组件 | 必需部件 | 缺了就显得没做完的那一件 |
| --- | --- | --- |
| 卡片 | 容器、主标识、一层支撑文字、产物或证据本身、一个动作、以及与产物绑定的元信息（日期、媒介、尺寸、职责） | 一个动作。三个链接互相争夺的卡片是列表；图片只作装饰而不作证据的卡片是模板格子 |
| 表格 | 说明"在比什么"的 caption、与列和行绑定的表头、单位列或表头带单位的约定、每种列类型的对齐规则、出处或统计周期行 | caption 与出处行。没有口径定义的数字，与[视觉验收](visual-review.md)里无来源的指标是同一个缺陷 |
| 导航 | 多于一个分组时的组标签、当前位置标记、每层条目数的上限、溢出行为、返回路径 | 当前位置标记与溢出行为。既不说"你在哪"、又无限制生长的导航只是一串链接 |
| 输入 | 不靠 placeholder 承担标签、字段本身、格式不自明时的说明文字、预留了位置的行内错误区、提交动作 | 预留的错误区与说明文字。用占位符当标签会在输入瞬间消失，读者随即忘了这一栏要什么 |
| 控件（按钮、开关、选择器） | 命中区、静止边缘、对外暴露的状态、以及换语言仍然成立的名称 | 对外暴露的状态。见[交互状态](interaction-states.md)：没有状态的控件没什么可宣布 |

**检查。** 对渲染页面里每个组件实例，用选择器与无障碍树双向测试必需部件是否存在——每张表的 `caption` 与 `th[scope]`、每个输入框由 `for` 或包裹关系绑定的真实 `<label>`、每张卡片的一个主动作、导航里的 `aria-current` 或等价标记、表单中的错误区。按部件类型报告存在计数。任何必需部件在任何一个实例上缺失即为不通过，而缺失的实例数就是这条发现的量级。

## 兄弟元素要共享读者会扫的那条基线

一组卡片、一组列表项、一组表格行是一个组件，不是一堆组件。读者在纵向比较它们，所以被比较的那部分必须在一组之内落在同一条线上：动作、元信息、状态标记、以及标题块最后一行。

用结构决定，而不是事后卡高度。在一组兄弟元素内部把部件分成固定区——标识、元信息、动作，由设计定尺寸——和一个伸缩区——摘要、注记、描述——让伸缩区吸收内容差异。成组元素用网格时，嵌套网格或 subgrid 能让基线由构造保证成立；不可用时，接受"按该组最高内容推出的一个共享最小高度"，不接受"每项按自己内容决定高度"。溢出固定区的文字按明说的规则裁切，绝不允许把动作往下推。

然后在每个宽度检查这一组，因为 1440 上对齐的那一行到 390 会变成三个单项堆叠，此时共线的论证不再适用，但参差的论证依然适用：堆叠后各项高度相差悬殊的一组，读起来像坏掉的网格。

**检查。** 在无头浏览器的 1440、768、390 下，按容器把兄弟元素分组，并在组内报告每个可比部件 `top` 偏移的最大差值——操作链接、元信息行、状态标记。通过要求差值为零，或者仅当 `DESIGN.md` 写明该部件是有意错位时允许一个很小的容差。每行报一个数字；454／479／514 那条发现，在源码里看上去完全正常，量出来是三个不同的数。

## 层级必须落在哪里

命名这一页的那个元素承担展示级角色，它下面的各节标题承担下一档。层级被错误的元素承担，结果不是"标题小一点"，而是一页不知道自己讲什么。

几条换到任何行业都成立的规则：每路由一个 `h1`，且它大于该路由上其余任何一种文字角色；文本是页面身份的标题不能是一个被样式的 `<p>` 加一个指回自己的 `aria-labelledby`；案例页标题必须在每个宽度上都强过它第一个分节标题，包括把桌面展示字号原样带下来的窄屏。字号台阶取自[视觉方向](visual-direction.md)的模数比及其窄屏规则——宽度下降时标题与正文的倍数本身要缩小；解剖只决定哪个元素拿哪一档，不决定它多大。

**检查。** 对每条路由读取 `h1`、每个 `h2`、最大的 `h3` 以及正文段落的计算 `font-size`。通过要求 `h1` 大于该路由最大的 `h2`，且正文等于 token 值。在 1440 与 390 各报这两个数；17.5px 的 `h1` 对 40px 的 `h2` 这种倒挂，一次探针就能在任何站点上抓到。

## 数据放不下时

一张比容器还宽的表只有两个诚实答案，而选择依据是数据的形状，不是剩余空间。

- **保留表格并横向滚动，同时给出提示**——当读者的任务是比较各列：规格矩阵、论点在于两期之差的指标表、按窑次读的釉试片表。提示不是可选项：滚动一侧可见的切断边或渐隐、下一列内容露出的碎片、可键盘聚焦以便读屏与键盘用户取到被裁的单元格、以及写明屏外是哪几列的 caption。在某个平台出现、在触屏上不出现的原生滚动条不算提示。
- **让它回流**——当读者的任务是逐行往下读、而各列是同一件事的属性：时间线、单件标本的记录、每行都是一个小对象的清单。把每行渲染成带键值对的块，行序以及任何关于顺序的主张保持不变。
- **按判断裁列**——当只有部分列承载论点，留下这些，其余移到该行本来就连过去的详情里。在 `DESIGN.md` 里写明删掉了哪些列以及为什么；悄悄删掉是内容缺陷。

不能让容器替你做决定。480px 的表放进 291px 的区域而又毫无提示，被藏起来的就是切口右侧那些列——而在案例页里，那正是论点所在的位置。

**检查。** 在 390 与 768 下逐张表报告 `scrollWidth`、容器可视宽度，以及右边界超出可视区域的表头单元格数量。只要有表头被裁，通过就要求存在渲染出来的提示——边界处带非 none 渐变或不透明度台阶的遮罩、渐隐或边缘指示元素——加上该表滚动容器可用键盘到达，加上 caption 点名至少一个屏外列。若选了另一条答案，则改为断言没有任何表可横向滚动，且每个回流后的行在无障碍树里暴露键值对。两种情况下都要列出被裁的列，并把它们与上下文论证涉及的列对照。

## 必须收窄的导航

目录导航那条发现不是"换行难看"，而是溢出行为未定义：390 下那组条目没有任何规则，于是产出三行高度不一的条目，吃掉了第一屏。导航在动手之前要有三个决定：390 下每一层放得下几个条目、放不下的那些怎么办（带吸附的横向滚动、折叠面板、或者更少更短的条目集合——是被选出来的，不是默认的），以及导航在任何宽度上最多占视口的多少。手机上占掉三分之一屏幕的吸顶目录栏不是导航，而是读者必须滚过去才能读到它所描述内容的障碍物。

**检查。** 在 390 与 768 下报告导航自身高度占 `innerHeight` 的比例、条目折成的行数、以及同一行内条目高度的方差。通过要求该比例低于 `DESIGN.md` 写明的上限、行数不超过声明的行数、同一行条目高度一致。然后滚过导航的目标位置，断言当前位置标记在该偏移下依然正确。

## 顺序

先修解剖，再修表面与动效：基线不齐的卡片无论什么圆角都显得坏，被裁掉论点列的表格没有任何值得加动效的状态。检查必需部件是否存在，然后查兄弟对齐，然后查层级，最后查放不下时的处理。这几条通过之后，[表面、光与层次](surfaces.md)决定组件由什么材料构成，[交互状态](interaction-states.md)决定它们如何回应。
